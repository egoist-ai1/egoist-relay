# Egoist Relay 1.2.5 — личный выпуск Windows x64

Дата: 29 сентября 2026 года. Windows x64. Обновление установленной версии 1.2.4.

Личный установщик подготовлен: [скачивание и установка](../release/1.2.5/README.md). Проверены точный payload, обновление тестовой копии 1.2.4→1.2.5, повторная установка, удаление и ограниченные проверки существующих аккаунтов. Версия последнего публичного upstream релиза не установлена: у локального проекта нет Git remote.

Installer: **604 771 373 bytes**, SHA-256 `47B46EBD7F366EBC426C7C43A58396BCBB552622833518E6473EDA13E7B380BE`.

## Что изменено

- Личная сборка использует общий путь **Main/Telegram/X/Instagram/media → Relay SOCKS/DoH 17880 → собственный Xray 17881 → выбранный сервер**. Telegram bridge — 17884. Включаются selected private DoH и snapshot VLESS/REALITY/xhttp stream-up; живой Lagom и синхронизация с ним не требуются.
- Проверяются владельцы портов и дочерние процессы; чужие listeners не принимаются и не завершаются. Восстановление своих helpers имеет ограниченные задержки; нет прямого fallback или автоматической смены провайдера/туннеля.
- DNS назначений проходит выбранный HTTPS-провайдер через backend с проверкой TLS. Bootstrap имени нестандартного DoH — ограниченный Cloudflare/Google через тот же backend. Смена IP того же провайдера восстанавливается одной объединённой попыткой не чаще раза в 30 секунд. Начальное имя самого Xray-сервера может разрешаться через ОС.
- Исправлены framing/backpressure/heartbeat и cleanup Telegram bridge, ранний SOCKS EOF, наследование общих proxy/Node options и разные сетевые пути media workers. Журнал и буферы ограничены.
- Копирование изображения, ссылки и текста документа сообщает результат после завершения записи. Исправлены потеря задач очереди скачивания, social URL/MIME validation, ранняя отмена, cleanup `.part` и retry занятого share job.
- В titlebar исправлены выход кнопок за границу и необработанный resize rejection. Добавлены полные tooltip/доступные состояния, сетевой busy и reduced motion. DNS-статус обозначает выбранный маршрут/локальную инициализацию.
- CSP согласована с Vite; неиспользуемые installer/updater IPC удалены. Auto-updater отключён по умолчанию. Включён Node **24.21.0**, совместимые исправления зависимостей и bundled engine path.
- Собственные сетевые helpers и Node workers получения медиа запускаются с **BelowNormal CPU priority**. Личный XMUX ограничен пулом 2 (`maxConnections: 2`, `maxConcurrency: 0`); это не жёсткий предел всех TCP-соединений и может уменьшать burst throughput. Настройки Lagom не меняются. CPU priority не задаёт QoS или приоритет на удалённом сервере.
- Включён Xray из официального commit **47cfe999**, build `47cfe999-relay-go1.26.8`, с двумя upstream исправлениями stream-up races. Выбор движка, проверка совместимости и предупреждения сканера описаны в [аудите Xray](AUDIT-1.2.5-XRAY-ENGINE.md).

## Личный профиль и установка

Установщик создаёт `relay-dns.dpapi` и `relay-tunnel.dpapi` с DPAPI CurrentUser и ACL владельцу/SYSTEM, назначая путь включённого Xray. Эти результаты проверены в изолированной установке. На другом устройстве нужно запустить личный installer: DPAPI-файл другого Windows-пользователя не переносится простым копированием. Конфигурация — сохранённый снимок; обновление требует явного импорта/нового installer и штатного перезапуска.

Payload личного установщика содержит извлекаемые данные подключения. Дистрибутив предназначен только для устройств владельца. Relay не меняет системный DNS, proxy, firewall, интерфейсы/TUN/маршруты и не устанавливает службу Lagom; Windows VPN/WinDivert всё равно могут влиять на соединение с удалённым сервером.

Обновление выполняется новым NSIS installer после штатного выхода Relay через трей. Code signing и подписанный автоматический update channel отсутствуют.

Включён Microsoft offline WebView2 installer с проверенной подписью; для установки runtime не нужен отдельный download. Ветка устройства без WebView2 пока не проверена на чистой VM. Исправлены installer helpers для Windows PowerShell 5.1, включая наследованный PSModulePath; работающий Relay блокирует установку с exit 2 и сохраняется.

## Результаты, требующие аккуратной интерпретации

- Последовательность native save→cancel в первом профиле не получила terminal event. Отдельная отмена первой операцией в свежем профиле прошла; первоначальный неопределённый результат сохранён.
- Private commit всего собственного дерева с тремя WebView в soak: 1264,7–1282,1 МиБ. Это не RSS и не доказательство устранённой утечки или общего ускорения.
- Установочные прогоны использовали собственную регистрацию/protocol/profile. Production installer на пользовательскую установку не запускался; second PC и чистая VM ещё нужны.
- [Manifest](../release/1.2.5/release-manifest.json) и evidence содержат результаты без ключей подключения, chat text и account screenshots.

## Известные границы

Реальная запись OS clipboard и отправка сообщений не проверялись. Нет полного покрытия dynamic Telegram DC/CDN, UDP/IPv6/звонков, многочасовой матрицы разных сетей/VPN и чистой VM. Истечение DNS/VLESS профиля, лимиты сервера/сессий, CAPTCHA и изменения внешних сервисов остаются внешними причинами отказа. Геометрические/UI fixtures не доказывают идеальную плавность всего приложения.

Полные находки, доказательства и дальнейшие gates: [аудит 1.2.5](AUDIT-1.2.5.md). Scoped counts в [MEDIA](AUDIT-1.2.5-MEDIA.md), [UI](AUDIT-1.2.5-UI.md) и [NETWORK](AUDIT-1.2.5-NETWORK.md) относятся к этапам/подзадачам и не складываются с общими числами выше.
