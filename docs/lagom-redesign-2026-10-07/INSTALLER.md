# Фирменный установщик Sennit Setup

8 октября 2026, версия 1.7.1. Установщик в собственном окне вместо стандартного мастера NSIS: один exe, запустил, нажал «Установить», получил результат. Реальная установка на ПК владельца в рамках работы НЕ запускалась.

## Архитектура

`Sennit-Setup-<версия>.exe` = маленький Rust-exe (stub, 1,3 МБ) + payload (готовый Tauri NSIS-установщик, ~540 МБ) + хвост. Установку выполняет проверенный NSIS в тихом режиме `/S` (currentUser): хэш-проверка runtime, миграция legacy, запись деинсталлятора, `DisplayName=Sennit` остаются в `tauri/installer.nsh`. Новый код отвечает за окно, проверки, прогресс и итог. Деинсталляция штатная («Приложения и возможности»), деинсталлятор не менялся.

| Часть | Где |
|---|---|
| Крейт (свой Cargo.toml/Cargo.lock/target, не часть `tauri/`) | `installer/` |
| Окно: tao 0.37.1 + wry 0.57.0 (версии из `tauri/Cargo.lock`, сборка `--offline` из кеша) | `installer/src/ui.rs` |
| Интерфейс: один HTML, шрифты Onest/Unbounded/JetBrains Mono и логотип отдаются из exe по протоколу `setup://`, внешних ресурсов нет | `installer/ui/` |
| Движок: проверки, хэш, распаковка, NSIS, итог | `installer/src/engine.rs` |
| Формат хвоста | `installer/src/tail.rs` |
| Прогресс, проверки (чистая логика) | `installer/src/progress.rs`, `preflight.rs` |
| Win32 (реестр, мьютекс, ACL, процессы, DWM) | `installer/src/win.rs` |
| Сборка финального exe | `scripts/build-installer.mjs` (`npm run release:installer`) |

Иконка, версия, название «Sennit Setup» и манифест (`asInvoker`, UTF-8) встроены через `build.rs` (tauri-winres из кеша). Без явного манифеста Windows запросила бы UAC по слову «setup» в имени.

## Дизайн

Egoist DS, Lagom: монохром, Onest (текст), Unbounded 400 (заголовки), JetBrains Mono только для меток сетки и данных; тёмная тема и светлая по системной; кнопка основного действия — инверсия, радиус 12, пружина на нажатие, `prefers-reduced-motion` учтён. Окно 720×460 логических px, без рамки, DPI-aware (tao), перетаскивание за верхнюю полосу, свои «свернуть/закрыть», скругление углов через DWM (Windows 11; на Windows 10 углы прямые). Фирменная сетка: кресты в четырёх углах поля и индекс шага `01/04`..`04/04` (реальный номер шага: старт, подготовка, установка, готово). Отступление от `docs/brand/BRAND.md` (метки сетки «не в мастере установки») и от DESIGN.md (сетки нет на экранах ввода): сделано по заданию владельца; экран ввода тут один флажок, сетка на полях и не перекрывает контент. Если решите иначе, убирается удалением четырёх `.cross` и `.index` в `ui/index.html`.

Экраны: приветствие (установка / обновление / переустановка / «версия новее»), процесс (проценты, этап, счётчик МБ, четыре шага, статус-бар), просьба закрыть Sennit, ошибка (Повторить / Показать журнал / Закрыть), готово (Запустить Sennit / Закрыть), лицензия GPL v3 внутри окна (текст встроен). Статус-бар внизу: точка состояния, честный текст этапа, процент, версия, тонкая линия прогресса.

Снимки: `docs/lagom-redesign-2026-10-07/installer-screens/` (10 состояний × тёмная/светлая, `NN-имя-тема.png`) и два снимка настоящего окна `native-*.png`.

Способ снимков: `node installer/shoot.mjs <папка>` открывает тот же `ui/index.html` в Edge headless (режим предпросмотра без оболочки: параметры `?state=welcome|verify|prepare|progress|prompt|error|done|license&theme=dark|light`, события имитируются тем же кодом). Настоящее окно (`Sennit-Setup.exe --demo=progress`) снято PrintWindow без управления мышью и клавиатурой.

## Формат хвоста

`[stub][payload][meta JSON][trailer 128 байт]`, little-endian, строгая арифметика: `payload_offset + payload_len + meta_len + 128 == длина файла`.

| Смещение | Размер | Поле |
|---|---|---|
| 0 | 8 | магия `SENNITSX` |
| 8 | 4 | версия формата (1) |
| 12 | 4 | флаги (0) |
| 16 | 8 | payload_offset (= длина stub) |
| 24 | 8 | payload_len |
| 32 | 8 | install_bytes (ожидаемый размер установки, для прогресса) |
| 40 | 4 | meta_len (≤ 64 КБ) |
| 48 | 32 | SHA-256 payload |
| 80 | 32 | SHA-256(meta ‖ trailer[0..80]) |
| 120 | 8 | магия конца `XSTINNES` |

meta: `{product, version, payloadName, builtAt}`; `payloadName` — только `[A-Za-z0-9._-]`, не с точки. SHA-256 защищает от порчи и случайной подмены; подлинность даёт только подпись Authenticode, её в этой версии нет. Порядок для подписанного выпуска: сначала собрать скриптом, потом подписать ГОТОВЫЙ файл (Authenticode хэширует и наложение, поэтому подпись после сборки валидна). При чтении хвоста установщик разбирает PE: если запись IMAGE_DIRECTORY_ENTRY_SECURITY указывает на сертификат строго в конце файла, длина файла считается до сертификата, и подписанный файл проходит `--verify` и установку (тест `signed_file_with_certificate_after_tail_is_accepted`). После подписи пересчитать хэши: `node scripts/build-installer.mjs --rehash`.

## Шаги установки

1. Проверка системы: Windows ≥ сборки 18362, прежняя версия не новее (откат запрещён, как в NSIS), длина папки ≤ 208 символов (то же число, что в `installer.nsh`), свободное место на томе установки и temp (суммируется, если том один).
2. Закрытие Sennit: если запущен `Egoist Relay.exe` из каталога установки, окно просит закрыть его через трей и само продолжает, когда он закрыт. Принудительно не завершаем: так же, как `installer-processes.ps1` (активные аккаунты). В `--silent` — ошибка с кодом 12.
3. Проверка целостности: SHA-256 payload внутри exe с хвостом, прогресс по байтам.
4. Распаковка: временная папка `%TEMP%\Sennit-Setup-<pid>-<nanos>` с ACL «владелец + SYSTEM, без наследования»; хэш записанных байт; файл переоткрывается дескриптором «чтение, без записи/удаления для других» и хэшируется ещё раз, дескриптор держится до конца NSIS, поэтому подмена между проверкой и запуском невозможна (проверено тестом).
5. Запуск `payload.exe /S` (больше ничего, кроме установленного Sennit по желанию, не запускается). Прогресс: максимум из байт, записанных процессом NSIS (`GetProcessIoCounters`), и роста каталога установки от минимума; шкала только растёт и до конца NSIS не доходит до 100 % (потолок 99 %). Общая шкала: проверка 0–8 %, подготовка 8–25 %, установка 25–100 % (доли шкалы, не времени).
6. Проверка результата: код NSIS 0, `Egoist Relay.exe` на месте, `DisplayVersion` в реестре не ниже ставимой.
7. Очистка: временная папка удаляется всегда (в том числе при ошибке и панике); устаревшие `Sennit-Setup-*` старше суток и журналы старше 14 дней чистятся при старте.
8. Запуск Sennit, если включена опция «Запустить после установки» (по умолчанию включена): процесс отсоединён от установщика.

Сторож: если NSIS 5 минут ничего не пишет (ни записи процесса, ни роста каталога), окно разблокирует «Прервать» (закрытие окна в этот момент тоже прерывает): процесс NSIS завершается, ошибка `SETUP-NSIS-STALL`, «Повторить» безопасно. Если запись возобновилась, кнопка снова блокируется. NSIS живёт внутри `TempGuard`: при любой ошибке или панике guard дожидается процесса и только потом удаляет папку, а повторный запуск до этого невозможен (`running`).

Отмена: пока идёт проверка/распаковка — безопасна (кнопка «Отмена», Esc, закрытие окна; временные файлы удаляются). Когда NSIS пишет файлы, закрытие окна блокируется с пояснением в статус-баре, пока он не завершится: полуустановка не создаётся нашим действием.

Ошибки (понятный текст, код `SETUP-*`, подсказка): нет места, антивирус (Win32 225/226), отказ доступа, NSIS остановился проверками (1), Sennit запущен (2), иной код NSIS, повреждённый payload, старая Windows, откат версии, длинный путь. Журнал: `%TEMP%\Sennit-Setup-<версия>-<UTC>.log`, кнопка «Показать журнал» открывает его в блокноте.

Один экземпляр: именованный мьютекс (`Local\SennitSetup-…`), второй запуск показывает единственное стандартное окно с сообщением и выходит с кодом 3.

Нет WebView2 (окно не создалось): запасной путь запускает payload в штатном русском мастере NSIS, который сам поставит WebView2. Если при этом запущен Sennit, показывается окно «Повторить / Отмена» (без вечного ожидания); отмена даёт ошибку `SETUP-APP-RUNNING`. При падении NSIS или непройденной проверке результата подсказка упоминает WebView2, когда установленный Runtime старше 143.

## Защита от подмены библиотек и процессов

exe обычно лежит в «Загрузках», где могут оказаться чужие DLL. Принято: статическая CRT (`installer/.cargo/config.toml`: `crt-static`, в импортах нет VCRUNTIME140/api-ms-win-crt); `dwmapi`, `comctl32`, `bcryptprimitives` подгружаются отложенно (`/DELAYLOAD` + `delayimp.lib` в `build.rs`), а первым действием `main` вызывается `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32)`; DWM-вызов сделан через `LoadLibraryExW` из System32. Остальные импорты (user32, kernel32, advapi32, gdi32, ole32, oleaut32, shell32, shlwapi, imm32, combase, ntdll, api-ms-win-core-synch) относятся к KnownDLLs или системным API-set. Блокнот для журнала запускается по абсолютному пути из `GetSystemDirectoryW`. Таблица импортов проверена разбором PE собранного exe (`IMPORT`/`DELAY`).

## Ключи командной строки

`--silent` (также `/S`, `-s`, `--quiet`): без окна, прогресс в консоль родителя; `--launch` запустить после установки; `--no-launch` в окне снять опцию; `--verify` проверить встроенный пакет и выйти (код 0 или 10); `--demo[=full|fail|running-flow|welcome|verify|prepare|progress|error|running|done]` интерфейс без payload; `--theme=dark|light`; `--exit-after=<сек>`; `--autostart` (с `--demo`, для автопроверок).

Коды выхода: 0 успех, 1 отмена, 3 уже запущен, 10 payload отсутствует/повреждён, 11 нет места, 12 Sennit запущен, 13 ошибка NSIS/доступа, 14 проверки (Windows, откат, путь), 15 внутренняя.

Обновление поверх установки: при `/S` страница повторной установки NSIS не запускается (на это рассчитан `installer.nsh`), старый каталог не удаляется, файлы перезаписываются; профили и настройки лежат вне каталога установки и не затрагиваются. Единственное удаление при `/S`: проверенный по SHA-256 список устаревших файлов сетевого runtime (`installer-legacy-runtime.json`). Папку выбрать нельзя: NSIS берёт прежнюю из реестра либо `%LOCALAPPDATA%\Egoist Relay`; собственный выбор папки потребовал бы системного диалога и риска длинного пути, поэтому не сделан.

## Как собрать

```sh
npm run tauri:build                         # NSIS payload (делает координатор)
# в ASCII-пути (junction), без сети:
New-Item -ItemType Junction -Path C:\e\inst -Target '<проект>\installer'
cd C:\e\inst; cargo build --release --offline        # installer\target\release\Sennit-Setup.exe
cd <проект>; node scripts/build-installer.mjs        # пишет в .part, проверяет размер и `--verify`, затем rename; чужие строки SHA256SUMS и поля manifest (включая installer/executable) сохраняются, добавляется секция `sfx`; release\<версия>\Sennit-Setup-<версия>.exe + SHA256SUMS.txt + manifest.json
```

Скрипт пишет файл потоково (≈2 с на 540 МБ), считает SHA-256, оценивает `install_bytes` как сумму `Egoist Relay.exe` и ресурсов из `tauri.conf.json` + 1 МБ на деинсталлятор (для 1.7.1: 603 662 109 байт; NSIS пишет файлы в распакованном виде, поэтому оценка близка к записанному объёму). Исходный NSIS-установщик в `release/<версия>/` не копируется: он остаётся в `tauri/target/release/bundle/nsis/` и лежит внутри exe; прежний файл `Egoist Relay_<версия>_x64-setup.exe` в `release/1.7.1/` скрипт не трогает и не удаляет. Скрипты `release-policy`/`release-preflight` состав `release/` не сверяют, менять их не потребовалось.
