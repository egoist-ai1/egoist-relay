## 2. Баг со скриншота: «Выберите получателей»

Компонент: `src/components/multi/SocialShareModal.tsx` поверх `RecipientPicker` → `ChatOrUserPicker`. Для воспроизведения в харнессе добавлены: `__relayAudit.openShare(request)` с настоящим `SocialShareModal` и двумя папками (`scripts/relay-ui-audit.fixture.tsx`), скрипт `scripts/qa-lagom/share-modal.mjs` (3 размера окна × 100/200 % × 2 темы, выбирается получатель, чтобы нижний блок был максимальным: «Скачать оригинал», «Copy link», «Отправить», переключатель Ссылка/Медиа/Файл, длинный текст, сообщение об ошибке).

Причина: диалог фиксированной высоты (`38.75rem`, максимум 80 % окна); шапка (поиск, недавние контакты, вкладки папок) не имела предела, нижний блок до 60 % высоты; список чатов получал остаток и ничем не защищался. На 1920×1080 при 100 % остаток был 34 px.

Исправление:

- нижний блок: потолок 50 % и прокручиваемая область деталей до 6,5 rem; кнопки закреплены внизу;
- шапка пикера (`.picker-header`): `max-height: 50 %`, внутренняя прокрутка, поле поиска липкое;
- область списка: `min-height: min(12rem, 45 %)` у внешнего блока и `6rem` у внутреннего, поэтому список не сжимается ниже минимума при любом масштабе;
- диалог растёт вместе с окном: `height: min(46rem, 100 % − caption − 0.5rem)` (на 1080 — 736 px вместо 620);
- на низком диалоге (`@container pickerDialog (max-height: 34rem)`): скрываются недавние контакты, строка источника и пояснение режима; режимы и кнопки компактнее, три кнопки в одном ряду.

Числа (видимая высота списка, px; Lagom Dark = Lagom Light):

| Окно | 100 % до | 100 % после | 200 % после |
|---|---|---|---|
| 640×448 | 56 | 97 | 28 (полоса прокрутки; эквивалент окна 320×224) |
| 800×560 | 56 | 209 | 56 |
| 1920×1080 | 34 | 196 | 379 |

Кнопка «Отправить» целиком внутри диалога и по горизонтали, и по вертикали во всех 12 конфигурациях. [проверено] Скриншоты: `screens/share-modal/before` (Lagom Dark, 100 %) и `screens/share-modal/after` (12 конфигураций + `share-geometry.json`). Проверка воспроизводится командой `OUT=<папка> node scripts/qa-lagom/share-modal.mjs` (код возврата 1 при нарушении порогов: видимый список ≥ 96 px при 100 %, ≥ 24 px при 200 %, кнопка внутри диалога).

Ограничение: при 200 % на 640×448 и 800×560 (эквивалент окон 320×224 и 400×280) в диалоге остаются заголовок, поле поиска, фрагмент списка и ряд кнопок; список прокручивается, область деталей сжимается до полосы. Больше при этих размерах физически не поместить.

## 5. Плавность и быстродействие

Метод: в харнессе (headless, 180 Гц, без GPU) снимались интервалы кадров и long tasks на переходах: смена темы, открытие чата, экраны настроек (General, Privacy), Ctrl+J открыть/закрыть, модалка шаринга. [проверено]

| Переход | p50 кадра | p95 | максимум | long tasks |
|---|---|---|---|---|
| простой | 5,6 мс | 5,7 | 27,8 | 0 |
| смена темы (светлая / тёмная) | 5,6 | 5,7 | 49,9 / 27,8 | 0 |
| экран настроек General / Privacy | 5,6 | 5,6 / 5,7 | 5,7 / 5,9 | 0 |
| открытие чата | 5,6 | 5,7 | 5,7 | 0 |
| Ctrl+J открыть / закрыть | 5,6 | 5,6 / 5,7 | 11,2 / 11,1 | 0 |
| модалка шаринга | 5,6 | 5,6 | 27,8 | 0 |

Проверено по коду и измерено:

- `getChatHeightPx()` (F-19) вызывает `getComputedStyle(document.documentElement).fontSize` на каждый рендер списка чатов и на каждый кадр анимации перестановки. Замер: 0,5 мкс при чистом стиле и 0,75 мкс сразу после записи `style.transform` (разница с записью без чтения 0,5 мкс). Узкого места нет, кэш не добавлялся; новый `getPeerPickerItemHeightPx()` использует ту же функцию.
- Relay-специфичные стили (`AppSidebar`, `Titlebar`, `MediaOperationsPanel`, `SocialShareModal`, `InlineSocialMedia`): переходы только по `color/background/border/opacity/transform`, длительность 140 мс, у каждого бесконечного или входного движения есть `prefers-reduced-motion`. Анимаций по `width/height/top/left` в этих файлах нет.
- Прогресс загрузок уже склеивается таймером на основе `scheduleProgress` (`mediaOperations.ts:136-147`): IPC не уходит на каждый сетевой блок.
- `backdrop-filter` встречается в 74 местах, в основном прежний код Telegram Web A (меню, реакции, медиа-оверлеи); в Relay-коде — `DocumentReaderModal.module.scss:27` (`::backdrop`, `blur(0.25rem)` на весь экран при открытии читалки). Стоимость размытия на GPU без GPU-профиля не оценить, поэтому ничего не менялось. [не проверено]
- `will-change` в Relay-коде не нужен: движущиеся элементы анимируются через `transform/opacity` с короткими переходами.

Изменения плавности не вносились: проверяемых узких мест headless-замер не показал. Одиночный кадр 49,9 мс при смене темы — единовременный пересчёт стилей всего документа, не повторяющаяся нагрузка.
