Дата: 7 октября 2026. Проект: Egoist Relay 1.6.1 (Tauri 2 / Rust, Teact/GramJS-форк Telegram Web A, WebView2-профили на сервис). Все источники открыты 07.10.2026, если не указано иное. Приложение не запускалось и не менялось; `.env` не читался.

## 0. Как читать отчёт

Статусы утверждений:

- **[проверено]**: первоисточник (официальная страница, GitHub API/страница репозитория/issue, changelog, исходник) прочитан через WebFetch. WebFetch пересказывает страницу малой моделью, поэтому пункты с пометкой **★** я перепроверил повторным независимым запросом.
- **[наблюдение]**: из обзоров, отзывов, сниппетов поиска, зеркал или вторичных пересказов.
- **[гипотеза]**: мой вывод из фактов.
- **[не проверено]**: подтверждения нет или источники расходятся.

Реклама и заявления вендора помечены «заявл.» и не считаются фактами о качестве.

Слепые зоны (честно):

- Reddit недоступен для WebFetch/WebSearch в этой среде. Фразы вида «на Reddit жалуются» в отчёте отсутствуют намеренно. Habr: статья 1018740 вернула 403, читались только комментарии к новости 1018232. 4PDA: только поисковая выдача.
- `core.telegram.org`, `telegram.org/tos` недоступны из среды (отказ соединения). Условия Telegram прочитаны через зеркало Open Terms Archive (OTA) и пересказы поиска, то есть это **[наблюдение]**, а не чтение оригинала.
- Instagram Terms, X ToS, X Help: оригиналы не отдали текст (JS/402/403); использовано зеркало OTA.
- Страницы Linear (`/now/behind-the-latest-design-refresh`, changelog 2026-03-12) и Superhuman (блог про command palette) три раза завершились таймаутом при прямом чтении: их содержание в разделе 3 взято из сниппетов поиска и помечено **[наблюдение]**.
- Замеров производительности самого Relay и конкурентов не проводилось. Все «память/скорость» цифры сторонних подборок это реклама или SEO-обзоры.

## 1. Что такое Relay сейчас (из README, AGENTS.md, DESIGN.md, исходников)

Контекст нужен, чтобы отличить «уже есть» от «пробел».

- Rail 4.5rem + caption 2.5rem, панель «Загрузки и пересылки» по Ctrl+J, 11 вариантов темы, Egoist Dark по умолчанию [проверено, `docs/DESIGN.md`].
- Каждый сервис в своём `data_directory` (X, Instagram, mini-apps, media-operations, research-social) и добавляется как child-webview через `add_child`; везде `disable_drag_drop_handler()` [проверено, `tauri/src/multi_app.rs`, `lib.rs`, `bot_web_apps.rs`].
- Для X заданы свои `additional_browser_args` (отключение msWebOOUI/msPdfOOUI/SmartScreen, autoplay, `host-resolver-rules` для twimg) [проверено, `multi_app.rs:43`].
- Cargo: `tauri =2.12.0` с фичами `devtools, tray-icon, unstable`, вендорный патч `tauri/vendor/`, плагины notification, updater, deep-link, single-instance, shell, fs, os, log, process [проверено, `tauri/Cargo.toml`]. Плагина `global-shortcut` нет.
- Есть собственный воркер транспорта Telegram `telegram_transport.rs` (локальный URL с токеном, супервизор с восстановлением) и `system_proxy.rs`; подробности реализации намеренно не разбирались [проверено по заголовку файла].
- Layer GramJS-форка в дереве Relay: **228** [проверено, `src/lib/gramjs/tl/AllTLObjects.ts`]. Upstream Web A на 29.09.2026: **229** ★ (см. 5.4).
- В `tauri/src` нет упоминаний `MemoryUsageTargetLevel`/`TrySuspend` (вендорный `tauri/vendor` не проверялся) [проверено grep]. В `src/` нет командной палитры [проверено grep].
- Ghost mode и сохранение удалённых сообщений в Relay отсутствуют [проверено grep по `src/global`].
- Публичный релиз требует corresponding source для сторонних бинарников; README сам признаёт, что inventory неполон [проверено, `README.md`].

### 5.2 WebView2: профили, прокси, память

- Профили: `ICoreWebView2Environment10::CreateCoreWebView2ControllerOptions`, `ProfileName`, `IsInPrivateModeEnabled`; несколько профилей в одном user data folder ★ (Microsoft Learn, страница обновлена 26.11.2025). Microsoft прямо пишет, что отдельная UDF на каждый control запускает отдельный runtime (браузерный процесс и дочерние) и расходует больше памяти, CPU и диска ★.
- Прокси: официальный механизм это флаг `--proxy-server` в `AdditionalBrowserArguments` (страница webview-features-flags; предупреждение, что флаги не рекомендуются в production и могут измениться) [проверено субагентом]. Аргументы применяются к environment, то есть к паре «UDF + опции»; отдельного API прокси на профиль или webview в SDK не найдено (WebView2Feedback #132 открыт с 06.03.2020) [наблюдение]. Аутентификация: событие `BasicAuthenticationRequested` (`ICoreWebView2_10`) охватывает Basic, Digest, NTLM и Proxy Authentication [проверено субагентом]. Работа WebSocket и PAC через `--proxy-server` в документации не подтверждена: нужен собственный тест [не проверено].
- Tauri tauri#10037 (SOCKS5 `proxy_url` не работает на Windows, закрыт 11.09.2025): субагент сообщил, что мейнтейнер объяснил привязку конфигурации прокси к data directory; мой повторный запрос этого пояснения не показал (страница без комментариев) [наблюдение, не подтверждено].
- Вывод [гипотеза, согласуется с документацией]: прокси на сервис возможен только при отдельной UDF на сервис. Relay уже так устроен (отдельные `data_directory`), значит платит N процессными группами за возможность разных сетевых путей. Если у X и Instagram одинаковая сеть, их можно было бы вынести в профили одной UDF, но разные `additional_browser_args` (X имеет специальные) этому мешают.
- Память: `MemoryUsageTargetLevel` (`ICoreWebView2_19`, SDK 1.0.1823.32): Low/Normal, скрипты и сеть продолжают работать, нельзя смешивать с `TrySuspend`/`Resume` (они сами меняют уровень); `TrySuspend` останавливает скрипты и сеть, уведомления из такого webview не придут [проверено субагентом по Microsoft Learn]. Для Relay: Low подходит скрытым X/Instagram; Telegram не усыплять.
- Утечки при закрытии: WebView2Feedback #1424/#4286 [не проверено, только заголовки].

| Аспект | Tauri 2 (WebView2) | Electron |

Вывод: переход на Electron ради прокси на сессию не нужен, пока сеть сервисов задаётся один раз; зато он даст `setProxy` на лету. Решение «остаёмся на Tauri» [гипотеза], подтвердить замером 1/3/10 профилей по сумме Private Bytes дерева `msedgewebview2.exe` (в этой сессии не измерялось).

Обходы для Tauri: (1) отдельная UDF + `proxy_url` на профиль (как сейчас); (2) локальный прокси-роутер: порт на профиль, смена апстрима без пересоздания webview [гипотеза]; (3) один environment + аутентификация, маршрут по логину через `BasicAuthenticationRequested` (требует COM-доступа, не проверено, что wry его выставляет) [гипотеза]; (4) `tauri-runtime-cef` 3.0.0-alpha.5 (альфа, Windows не оценён) [наблюдение].

Замечание: wry при заданных `additional_browser_args` может не добавлять `--proxy-server` (чтение исходника на ветке dev субагентом, тег 0.57.0 не проверен) [наблюдение]. Если Relay когда-либо задаст прокси X/Instagram через `proxy_url` вместе с `X_SERVICE_BROWSER_ARGUMENTS`, это надо проверить тестом.

### 5.6 MTProto через прокси в браузерном окружении

- Оригиналы `core.telegram.org/mtproto/mtproto-transports` и `/proxy` не открывались (см. раздел 0): формат транспортов и секретов взят из сторонних источников.
- В Web A транспорт это `PromisedWebSockets` (`wss://…/apiws`, подпротокол `binary`), прокси-настроек в `Connection.ts` нет; есть обфускация `ObfuscatedIO` и HTTP-транспорт с long-polling [проверено субагентом по исходникам].
- Секреты MTProxy: обычный, `dd`+padding, `ee`+домен (fake TLS) [наблюдение]. Fake TLS требует TCP-потока; в браузере только WebSocket/HTTP, поэтому браузерный клиент не может говорить с `ee`-прокси напрямую [гипотеза, согласуется с источниками].
- Известные мосты: Flowseal/tg-ws-proxy (TCP клиентов в WebSocket на DC Telegram; обратное направление, MIT, 10.4k звёзд) [проверено субагентом]; подмена `window.WebSocket` (TG-WebApp-Proxy) [наблюдение]. Relay имеет собственный воркер `telegram_transport.rs` (локальный URL и токен), то есть уже решает ту же задачу; сравнивать устройство с описанными схемами не входило в задачу.
- WEB-тип прокси в tdesktop 7.1: добавлен ★. Остальное (HTTPS/WebSocket-кадры, `ee`-секреты не принимаются, ссылки `t.me/webproxy`) из сторонних статей [не проверено].
- РФ: DPI блокирует MTProto по сигнатурам и ClientHello (с 22.05.2026 по tdesktop #30733), блокировки идут волнами и по регионам [наблюдение]; ru.wikipedia (по пересказу) фиксирует замедление Telegram с 10.02.2026 и штраф 35 млн руб. 16.03.2026 [наблюдение]. Вывод: любая схема обхода недолговечна, нужны видимое состояние и быстрое переключение.

## 6. Юридические и ToS-факты

### 6.1 Telegram

- API Terms (зеркало OTA «Developer Terms», версии с 2020 по 02.07.2026) [наблюдение]: нужен собственный `api_id` (2.1); факт использования Telegram API должен быть заметно указан (2.2); слово «Telegram» в названии допустимо только с «Unofficial» (2.3, пересказ); нельзя использовать логотип Telegram (2.4); не вмешиваться в базовую функциональность, примеры: действия от имени пользователя без его ведома, отключение самоуничтожения, подмена статусов last seen/online/read/typing (1.4); приложение, показывающее контент каналов, должно поддерживать sponsored messages и не мешать им (3.3); при нарушении Telegram уведомляет аккаунт, и если за 10 дней не исправлено, может прекратить доступ к API и обратиться в магазины (4.1-4.2); данные нельзя использовать для обучения AI/ML (1.5).
- Content Licensing and AI Scraping (telegram.org/tos/content-licensing): доступ к пользовательскому контенту для чего-либо, кроме обычного использования платформы, запрещён; есть ограниченное исключение для данных, необходимых легитимному стороннему клиенту, боту или Mini App; OTA зафиксировал добавление явного запрета 03.02.2026 (заметка OTA) [наблюдение]. Для Relay это касается исследовательского MCP, читающего данные Telegram.
- `api_id`: tdesktop `docs/api_credentials.md` говорит, что встроенные тестовые ключи только для тестов, иначе ошибки при входе [проверено субагентом]. README telegram-tt: свой API ID и hash в `.env` [проверено субагентом].
- Лицензии: tdesktop GPLv3 + OpenSSL exception; telegram-tt GPL-3.0 [проверено субагентом].
- Неофициальные клиенты: AyuGram документально называет себя форком «with ToS breaking features» (docs.ayugram.one) [проверено субагентом]. - Whisper: MIT (код и веса) [проверено субагентом]. Xray-core: MPL-2.0; `wintun.dll` идёт под Prebuilt Binaries License [проверено субагентом]. MTProxy: в репозитории файлы GPLv2 и LGPLv2 без привязки к коду [не проверено].

### 7.3 Ловушки (чего не делать)

1. Ghost mode, скрытие прочтения/набора, сохранение удалённых сообщений: API Terms 1.4 прямо перечисляет такие вмешательства; AyuGram сам называет их нарушающими правила [наблюдение/проверено]. Риск для `api_id` Relay.
2. Скрытие или подавление sponsored messages: API Terms 3.3 [наблюдение].
3. Переход на npm `telegram` (мёртв) или на `teleproto` (только Node): для браузерного воркера не подходят. Миграция на `mtcute` = переписывание слоя API [проверено субагентом/гипотеза].
4. Переход на Tauri 3 alpha или `tauri-runtime-cef` сейчас: альфа, Windows не оценён [проверено субагентом].
5. Пакетная загрузка профилей Instagram и автоматизация действий в X/Instagram: instaloader #2555/#2680, ToS X «No scraping, browser automation», Instagram 4.2 [наблюдение/проверено субагентом]. Сохранять то, что пользователь сам открыл.
6. Приватные API Instagram (как IG:dm) вместо веб-интерфейса [наблюдение].
7. Подписки, лимиты бесплатного тира, облачная синхронизация, телеметрия: это боли Ferdium/Rambox/Franz/Beeper и противоречит цели «local-first» [проверено/наблюдение].
8. Счётчики непрочитанного только из DOM чужого сайта без запасного пути [наблюдение: Ferdium #2416, #2518].
9. Опираться на флаг `--proxy-server` без теста WebSocket/PAC и без проверки, что `additional_browser_args` не отключает прокси в wry [не проверено].
10. Передавать содержимое Telegram через MCP моделям для обучения или внешним сервисам: API Terms 1.5 и Content Licensing [наблюдение]. Control API не открывать на сеть (уже в AGENTS.md).
11. Публикация установщика без полного corresponding source для сторонних бинарников (GPLv3 §6): README Relay уже отмечает пробел [проверено].
12. `devtools` в публичном релизе (AGENTS.md) [проверено].
13. Вшитые тестовые `api_id` в публичную сборку: ошибки входа у пользователей (tdesktop `api_credentials.md`) [проверено субагентом].
14. Скачивание JDownloader/yt-dlp не с официальных сайтов: много поддельных репозиториев [наблюдение].

### 7.4 Что осталось непроверенным

4. Реальное устройство `telegram_transport.rs`, `system_proxy.rs`, текущая логика уведомлений Relay, использование cookies в загрузках: не разбирались.

6. Поведение WebSocket, PAC и аутентификации прокси в WebView2 при `--proxy-server`; выставляет ли wry/Tauri `BasicAuthenticationRequested`; поведение `proxy_url` при заданных `additional_browser_args` на теге wry 0.57.0.

9. Версии и лицензии: Stacher, iMe Desktop, Shift, Rambox (коммерческий), 64Gram (лицензия), gallery-dl и Instaloader (лицензии), Dia (цена, Windows-выход), Vivaldi/Edge/Wavebox прокси per-profile.

11. Содержание Linear/Superhuman/Raycast первоисточников: читались только сниппеты; поведение трея и drag-and-drop-референсы без источников.

14. Реакции под Ferdium #2369 (число не подтверждено), активность tweb (служебные коммиты), Kotatogram (противоречие источников).
