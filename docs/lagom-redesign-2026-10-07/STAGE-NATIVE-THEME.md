# Этап «нативная тема»: фон WebView и тема окна (F-16)

Дата: 2026-10-08. Ветка `lagom-redesign`. Правки не закоммичены (коммитит координатор); `git commit/push/reset/checkout/stash` не запускались. Секреты не читались.

## Что сделано

Раньше подложка WebView X, Instagram и Mini App была жёстко `#000`, а окно принудительно получало `Theme::Dark`. На Lagom (`#0E0E0F` / `#F5F5F2`) это давало шов и вспышку чёрного при запуске и в светлой теме.

1. **Команда `relay_set_theme(background: String, is_dark: bool)`** в новом модуле `tauri/src/native_theme.rs`.
   - Вход строго `#RRGGBB` (7 байт, `#` + 6 hex-цифр, любой регистр). Сокращение `#RGB`, альфа, пробелы, имена цветов и многобайтные символы дают ошибку без паники.
   - Цвет и тема запоминаются в общем состоянии (`Mutex`, отравление замка не страшно). Значение по умолчанию до первого сообщения интерфейса — тёмный Lagom `#0E0E0F`, `Theme::Dark`. Альфа всегда 255.
   - Применение: `set_theme(Some(Dark|Light))` главному окну; `Webview::set_background_color` для `x_webview`, `instagram_webview` и всех `mini-app-*`; для отдельных окон (popup `mini-app-popup-*`, окна входа `x-auth-*`, `instagram-auth-*`) — `set_theme` и `WebviewWindow::set_background_color`. Окно `main` и исследовательские окна/WebView (`relay-research-*`) не перекрашиваются. Ошибка одного вида не прерывает остальные: команда применяет всё и возвращает сводку сбоев.
   - Цвет самих страниц X/Instagram/Mini App не менялся.
2. **Новые WebView берут сохранённое значение** вместо `#000` и `Theme::Dark`: `multi_app.rs` (создание X и Instagram, окно входа — тема и фон; `activate_x`/`activate_instagram` больше не сбрасывают тему главного окна в тёмную), `bot_web_apps.rs` (Mini App и popup).
3. **Capability**: отдельный `tauri/capabilities/native-theme.json` (`relay-native-theme`, `local: true`, webview `main`, разрешение `allow-relay-set-theme`). Команда внесена в `AppManifest::commands` (`tauri/build.rs`) и в `generate_handler!` (`lib.rs`). Сборка сгенерировала `tauri/permissions/autogenerated/relay_set_theme.toml` и обновила `tauri/gen/schemas/*` (в четырёх файлах есть `relay_set_theme`).
4. **Фронтенд**: `src/util/tauri/nativeTheme.ts` (`syncNativeTheme`) и одна строка вызова в `applyAntigravityTheme` (`src/util/antigravityThemes.ts`, плюс импорт). Фон берётся из `theme.variables['--color-background']`, `is_dark = theme.base === 'dark'`. Вызов идёт только при `IS_TAURI`, динамический `import('@tauri-apps/api/core')`, значение не вида `#RRGGBB` пропускается, одинаковые подряд вызовы не повторяются, ошибка логируется через `handleError` и сбрасывает дедупликацию (следующий вызов повторит попытку); исключение наружу не выходит.

## Ограничения

- **[не проверено]** в запущенном приложении: реальная смена фона дочерних WebView2, исчезновение вспышки и шва, смена цвета уже открытого Mini App/popup. Проверено только сборкой, юнит-тестами и ACL-preflight.
- Документация `set_background_color` (vendor `tauri` 2.12.0): на Windows альфа заменяется на 255, на macOS/iOS не реализовано. Для macOS команда вернёт ошибку в журнал фронтенда (`handleError`); сборка под macOS не проверялась.
- Фон главного окна и главного WebView (`main`) не задаётся: страница Relay рисует его сама; вспышка самого главного окна до загрузки HTML этим этапом не затронута.
- До первого вызова `relay_set_theme` (старт фронтенда) подложка тёмная Lagom; при светлой теме запуск покажет короткий тёмный интервал, пока интерфейс не пришлёт цвет.
- Команда не вызывает `require_main`: защита — capability (`local: true`, только `main`), как у соседних команд с одним webview.
- Окна исследований (`relay-research-*`) намеренно не перекрашиваются (скрытые окна чтения по запросу MCP).
- Вне этапа остались `cargo fmt --check` (до правок тоже не чист) и стили/иконки/QA-скрипты, которые правятся параллельно.
