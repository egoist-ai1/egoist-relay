# Удалённые сообщения (Relay 1.7.0, ветка lagom-redesign)

8 октября 2026. Функция: удалённое сообщение остаётся в ленте строкой «Сообщение удалено» (время удаления, стрелка), по клику раскрывается и показывает сохранённую копию. Метки: [проверено] / [не проверено].

## Риск для владельца (отдельный пункт)

Сохранение удалённых сообщений затрагивает условия API Telegram (разработчикам клиентов предписано удалять у себя то, что удалил собеседник). Владелец решил включить функцию для личного клиента, поэтому она управляемая и локальная:

- включена по умолчанию, выключается в Настройки → Конфиденциальность → «Удалённые сообщения»; при выключении копии перестают показываться, новые не сохраняются, сообщения удаляются как раньше;
- копии лежат только в IndexedDB этого компьютера (`tt-deleted-messages`), наружу не отправляются, при выходе из аккаунта стираются;
- кнопка «Очистить сохранённые» (с подтверждением), срок хранения (7/30/90/365 дней, по умолчанию 90) и лимит размера (50/200/500/1000 МБ, по умолчанию 200, вытесняются самые старые);
- не сохраняются: секретные чаты, сообщения с таймером автоудаления (`ttlPeriod`), медиа с самоуничтожением (`ttlSeconds`), служебные, эфемерные и локальные неотправленные сообщения.

Пользователь вправе выключить функцию в любой момент; для публичного релиза другим людям стоит оставить её выключенной по умолчанию или убрать — решение владельца.

| Строки | 16 ключей `Relay*Deleted*` в `fallback.strings` (русский), типы — `npm run lang:ts` |

Поток: приходит `updateDeleteMessages` / `updateDeleteChannelMessages` → если настройка включена, для каждого id берётся копия из глобального состояния до применения удаления → копия пишется в IndexedDB (по ключу `пользователь|чат|id`), сообщение остаётся в состоянии с `deletedAt` и рисуется строкой. Сообщение, которого не было в состоянии (канал или супергруппа, чат открывался в сессии), даёт запись без содержимого: после сохранения вызывается `restoreDeletedMessages`, строка появляется без раскрытия («Содержимое не сохранено…» в подсказке). Для личных чатов и обычных групп (обновление без `chatId`) чат по неизвестному id определить нельзя, запись не создаётся — ничего не выдумывается. После перезапуска действие `restoreDeletedMessages` кладёт копии обратно в `byId`, `listedIds`, outlying-списки и `viewportIds` только внутри уже загруженного диапазона истории (и хвост, если загружен конец истории; дата строки без копии берётся у соседнего сообщения).

Строка: кнопка с `aria-expanded`/`aria-controls`, Enter и Space работают как у нативной кнопки, фокус — контур 2 px цветом `--color-primary` (в Lagom это инверсия), раскрытие — появление панели за `--dur-base`, поворот стрелки на пружине; `prefers-reduced-motion` гасит движение глобальным слоем `reset`. Раскрытая панель: автор, «отправлено ЧЧ:ММ», пометка «удалено», миниатюра медиа (если в копии есть `thumbnail.dataUri`), текст или подпись. Строка без копии — не кнопка, а обычный элемент.

Свои удаления (`isDeletedByMe`) сохраняются и показываются так же; в записи стоит `isDeletedByMe: true`, «удалёнными собеседником» не помечаются.

## Не проверено и ограничения

- [не проверено] Живой Telegram и WebView2: только MockClient, юнит-тесты и Chromium-харнесс. Реальные `updateDeleteChannelMessages` и перезапуск приложения с настоящей историей не прогонялись; возврат копий проверен на редьюсере, а не на реальной подгрузке истории.
- [не проверено] Поведение прокрутки ленты при раскрытии строки в длинной истории, несколько вкладок/окон одновременно, стирание копий при выходе из аккаунта (код в `signOut` добавлен, теста нет), мобильная ширина.
- Копии возвращаются только в основной поток чата; форумы (темы) и обсуждения (комментарии) не поддержаны.
- Миниатюра — то, что клиент уже получил в сообщении (`thumbnail.dataUri`); сам файл не сохраняется и после удаления Telegram его не отдаст. «Превью медиа, если оно было в кеше» сведено к этой миниатюре.
- Очистка стирает копии всех аккаунтов этого профиля WebView2; настройка общая для профиля, а не для аккаунта; ключи записей включают id пользователя, при выходе стираются копии вышедшего.
- Очистка истории чата, удаление истории участника и темы (`deleteHistory`, `deleteParticipantHistory`, `deleteThread`) копий не сохраняют — это действия владельца или модерации, а не удаление отдельных сообщений.
- Прежнее поведение «Anti-Delete» (входящие остаются в ленте полным сообщением с бейджем, жёстко зашитая русская строка) заменено этой функцией; при выключенной настройке удалённое исчезает, как в обычном клиенте.
- Другие агенты параллельно правят `fallback.strings`, `language.d.ts`, `scripts/relay-ui-audit.fixture.tsx`: мои правки в первых двух добавлены точечно (`language.d.ts` перегенерирован `npm run lang:ts`, в нём есть и ключи сессий других агентов).
- Дату строки в харнессе показывает `Intl`; строки старого языкового пакета (`Time.TodayAt`) не используются.
