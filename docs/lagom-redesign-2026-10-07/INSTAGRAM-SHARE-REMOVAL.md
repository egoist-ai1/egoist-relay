# Удаление шаринга Instagram → Telegram

Дата: 2026-10-08. Ветка `lagom-redesign`. Коммитов нет. Шаринг X → Telegram сохранён без изменений поведения.

## Что удалено

| Место | Изменение |
|---|---|
| `scripts/social-share-enhancer.js` | Убраны все ветки Instagram: кнопка «Поделиться» в постах и рилсах, выбор рейла действий, плавающая кнопка, подмена подписей («Нравятся»), `instagramPostUrl`, медиахосты Instagram. Файл работает только для X; при `service !== 'x'` `initialize()` ничего не делает |
| `tauri/src/multi_app.rs` | Webview Instagram больше не получает `create_enhancer_script` (токен шаринга) и не перехватывает навигацию `egoist-relay-share://` — такая навигация теперь блокируется общей веткой «не внутренний URL». `INSTAGRAM_ENHANCER_SCRIPT` подключается как есть |
| `tauri/src/social_share.rs` | `validate_request` отвечает отказом на любой `service`, кроме `x` (константа `SHARE_SERVICE`); убраны ветки Instagram в `is_service_origin`, `is_media_url`, `service_label`, проверке пути; `multi_social_set_labels` обновляет подпись только в webview X |
| `src/components/multi/socialShare.ts` | `SocialShareRequest.service: 'x'`; `isSocialShareRequest` принимает только `x` |
| `src/components/multi/SocialShareModal.tsx` | Подпись источника всегда «X» (одна точечная правка) |
| `src/components/App.tsx` | Тип события `multi-social-share-error` сужен до `'x'` |
| `src/components/multi/MediaOperationsPanel.tsx` | Кнопка «Повторить» скрыта для старых записей журнала с `service: 'instagram'` (для них больше нет способа сделать новый захват) |
| `scripts/relay-reel-actions-alignment.test.mjs` | Удалён целиком: проверял только выравнивание рейла Instagram с кнопкой шаринга |
| `scripts/relay-social-share-reels.test.mjs` | Убраны сценарии шаринга рилсов и постов Instagram; получатель (реальный `App` + `SocialShareModal`) переведён на X |
| `scripts/relay-ui-audit.enhancers.mjs` | Убраны 3 кейса `ig-srcset-*` (фото Instagram через `social-share-enhancer.js`); `instagram-enhancer.js` проверяется как раньше |
| `scripts/relay-frontend-acceptance.mjs` | Кейс `saved-messages-icon-contrast` открывает модалку шаринга через X |

## Что оставлено (намеренно)

- Страница Instagram в приложении: просмотр, лайки, нативные «Сохранить»/«Поделиться» самой Instagram, `scripts/instagram-enhancer.js` (паузы видео, истории), `multi_prewarm_instagram`, `multi_instagram_navigate` и их capabilities/permissions.
- Нативные загрузки из Instagram (`multi_app_downloads.rs`, `MediaOperationKind::Download`, `service: instagram`) — отдельная функция, не связана с отправкой в Telegram.
- Инлайн-превью ссылок Instagram в сообщениях Telegram (`inline_media.rs`, `inlineSocialMedia.ts`, `InlineSocialMedia.tsx`) — другая функция.
- `media_operations.rs` и тип `MediaOperation.service` с `'instagram'`: журнал читает старые записи и записи загрузок. Новые операции `save`/`send` для Instagram больше не создаются (их создавала только модалка шаринга).
- Команды `multi_social_*` и `build.rs` AppManifest, `capabilities/*.json`, autogenerated permissions: команды общие с X и остаются на месте, поэтому лишних записей нет и менять манифест не нужно. Строки локализации шаринга общие для X; Instagram-специфичных строк шаринга не было.
- `tests`: `scripts/instagram-attribution-*.test.mjs` не связаны с шарингом, не тронуты.

## Известное следствие

Незавершённые или неудавшиеся записи журнала Instagram `save`/`send` от прошлых версий нельзя перезапустить: восстановление в Rust (`build_restored_share`) отклоняет `instagram`, а кнопка «Повторить» для них скрыта. Кнопка «Источник» остаётся.

## Тесты

- Rust (`social_share.rs`): `instagram_share_requests_are_rejected_in_every_form` (Instagram отклоняется как запрос, URL, медиа, метка webview и восстановление), `x_share_requests_still_validate_and_drop_query_strings`; старое утверждение о рилсе Instagram заменено на альбом X.
- vitest (`socialShare.test.ts`): `Rejects Instagram share requests in every form`.
- Playwright (`relay-social-share-reels.test.mjs`): `instagram-service-injects-no-button`, `instagram-article-post-injects-no-button`, `x-service-on-instagram-origin-not-initialized`, получатель `instagram-request-rejected`; сохранены 4 сценария X (родная группа, текст, оригинал фото, видео, неинициируемый клик) и обновление подписи.
