## Изолированная проверка установщика

Из финального сгенерированного NSIS-сценария собран проверочный клон с теми же EXE/runtime, отдельными именами продукта, registry-ключами и протоколом. Каталог установки жёстко ограничен временным каталогом проверки; ярлыки отключены. Это позволяет проверить установку и удаление без замены пользовательского Relay.

- Silent install `/S /NS`: код 0. EXE, Node.js, лицензия и прокси присутствуют.
- Скрытый запуск установленной копии: главное WebView2 и оба сетевых процесса готовы; stderr пуст.
- Silent uninstall: код 0. Удалены каталог установки, тестовый обработчик протокола и uninstall-key. Оставшийся уникальный тестовый settings-key очищен отдельно.
- Хеши существующих registry-настроек Telegram protocol и реальной установки Relay совпадают с состоянием до проверки.
- Тестовые процессы и listener-порты освобождены. Закрытие CDP target в проверочном клоне не является закрытием физического окна Tauri; для этого сценария выполнена точечная очистка только собственных процессов. В отдельном native smoke обычное закрытие главного окна завершило всё дерево автоматически.

Сам установщик с пользовательской идентичностью поверх действующей установки не запускался; это не проверка миграции всех существующих пользовательских данных.

## Границы результата

Новая регистрация Telegram API не выполнялась. Сохранены существующие параметры форка. В отдельных сетевых проверках Telegram возвращал `API_ID_PUBLISHED_FLOOD`; в финальном запуске QR был получен. Поэтому безошибочный вход для всех аккаунтов и сетей не заявляется.

MTProxy обслуживает Telegram; X использует системное подключение. Автономный туннель для обхода блокировки X не встроен. DNS, firewall и системный proxy не изменялись. Ограничения Telegram на стороне сервера сохраняются.

Вход в аккаунты, отправка сообщений, звонки, большие передачи и обновление реальной пользовательской установки не проверялись. Пользовательская установка не заменялась; готовый установщик передаётся отдельно.
