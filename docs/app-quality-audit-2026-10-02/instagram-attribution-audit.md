# Проверка атрибуции Instagram

Данные не доказывают, кто опубликовал два reel из выборки OpenAI и являются ли они совместными публикациями. Сохранены ссылки на /chatgpt/reel, но автор, подпись и дата не наблюдались. По URL нельзя подменять отсутствующее доказательство издателя.

## Что установлено

- Источник задания: openai. Обе записи имеют ссылки на официальный домен Instagram, пустой author и явные caption_not_observed/timestamp_not_observed. Они получены в контексте выбранной страницы, а не подтверждены как публикации этого автора.
- Описание каждой записи совпадает по SHA с описанием профиля из отдельно выбранного discovery. Это наблюдавшиеся метаданные страницы, но их источник не выделен в fieldEvidence/sourceContext.
- На обоих настоящих helper воспроизводится потеря OG-подписи при alias того же shortcode: старт принимает документ /reel/ID, но fallback caption сравнивает его с /chatgpt/reel/ID буквально.
- Синтетический точный DOM детали с header, h1 и time сохраняет эти наблюдённые значения. Даже несколько имён в header остаются observedText, не структурированным доказательством коллаборации.
- Чужая страница профиля и другой shortcode отвергаются до записей. Native код сохраняет строгую привязку к first-party origin, фактическому документу, выбранному target, аккаунту и epoch. Исполнение native здесь отдельно не проверялось.

## Проверка

Двенадцать сценариев на installed 1.4.2 и candidate 1.4.4: 8 проходят, 4 выявляют два нарушения контракта по одному на каждом helper. Ненулевой exit code ожидаем и сохранён — исправление не применялось. Документы синтетического браузера отдавались локально; все остальные запросы блокировались. В Relay, MCP, аккаунты и сетевые настройки обращения не выполнялись. Исходные публичные JSONL/manifest сохранили SHA.

## Предложения без применения

1. Отдельно сохранять наблюдаемую страницу и метаданные профиля: pageMetadata/sourceContext с проверенным native document locator. Отсутствие доказательства автора/коллаборации обозначать явно.
2. Для подписи детали использовать строгое сравнение того же поста по допустимым first-party kind/shortcode alias, согласованное с native нормализацией. Биографию профиля не выдавать за подпись поста.
3. Авторство и совместную публикацию устанавливать лишь по отдельным точным наблюдаемым данным выбранного поста. Не выводить автора из handle в URL.

Рекомендации и коллаборация как причина реальных ссылок остаются непроверенными: сохранённые записи не отмечают принадлежность узла к конкретной сетке профиля. Широкий selector main article/anchors не позволяет решить это задним числом.
