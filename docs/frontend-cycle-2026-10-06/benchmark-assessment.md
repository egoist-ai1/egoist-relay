# Парное сравнение: интерпретация результата

Запуск: [2026-10-06T12-27-37-098Z-ea6a13ef](benchmark/2026-10-06T12-27-37-098Z-ea6a13ef/README.md). Шесть batch, три чередующиеся пары, 1200 измеренных действий, по 20 наблюдений каждой метрики в batch. Во всех шести использован Edge **154.0.4258.62**, Node 24.19.0, headless, одинаковые данные/прогрев/RU/root16/1920×1080. Источники и harness не менялись во время запуска. Это frontend source-overlay, а не сравнение двух исторических установок.

**Отклик.** Порог регрессии: медиана кандидата выше на 10% и минимальная из трёх candidate batch medians превышает максимальную baseline. Ни одна из десяти временных метрик не пересекла оба условия. Открытие чата: 29,85 → 27,50 мс; история по Ctrl+J: 135,10 → 135,35 мс; переключение Telegram: 35,60 → 35,85 мс. Это наблюдения текущего host. По перекрытию диапазонов и трём повторам нельзя доказать эквивалентность либо общий выигрыш скорости. Проверка видимости на двух RAF и задержка native mock 15 мс включены в определение метрик.

**Память.** Конечные private bytes всего идентифицированного browser-дерева: медиана 889,68 → 844,51 МиБ, −5,08%. Диапазон baseline: 877,87–1758,08 МиБ, candidate: 842,87–855,79 МиБ. Третий baseline имеет 11 процессов и повышенную память уже до измеренных циклов; остальные batch имеют 10. Причина этого выброса не установлена. Удалять выброс ради красивого результата нельзя. Эти endpoint snapshots не являются пиком; снижение памяти не считается доказанным устойчивым эффектом.

**CPU — сравнение недоступно.** В каждом batch обе Windows-точки имеют полный охват CDP PID, нет пропущенных процессов. Однако один PID завершился и другой появился между точками во всех шести batch; набор CDP тоже изменился. Поэтому правило точной разности cumulative CPU всего дерева не выполнено: `browser-tree-cpu` и `browser-cdp-cpu-crosscheck` имеют `incomplete`. Число процессов само по себе не доказывает идентичность дерева. CPU завершившегося процесса нельзя восстановить из конечного Get-Process/CDP snapshot; значения не подменены нулём и не суммированы по оставшимся PID. Тип и причина замены не устанавливаются сохранёнными PID/PPID, догадка о процессе здесь не представлена как факт.

Это ограничение прибора, а не измеренная CPU-регрессия. Для честного полного CPU сравнения понадобится учёт времени жизни процессов и завершений либо native trace установленного Relay. Повтор такого же двухточечного измерителя без изменения метода не устраняет потерю данных. В рамках текущего доступа подтверждены временные метрики и конечная память; сумма CPU всего native Tauri/WebView2-дерева остаётся непроверенной.

**Среда.** Текущие audit harness/dependencies/configFile:false и APP_VERSION macro 1.6.0 общие для обеих ветвей. В frozen baseline отсутствуют vite.config.ts, tsconfig.json и tsconfig.base.json; они прямо перечислены в source-identities.json и не выданы за исторические. Node/Vite не включены в ресурсное browser-дерево. Windows probes и CDP имеют разные временные brackets. Живые аккаунты, реальные файлы, физические DPI/GPU и installed native GUI не участвуют.

При текущих данных регрессий, требующих изменения продукта по принятому порогу, нет. Доказанный функциональный выигрыш этого цикла — место для чтения, контраст и восстановление фокуса/темы; он не превращается в обещание кратного ускорения.
