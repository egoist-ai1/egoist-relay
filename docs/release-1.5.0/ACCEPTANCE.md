# Живая приёмка 1.5.0 — только своё «Избранное»

Статус: ожидается участие владельца. Ни одна реальная отправка в аккаунт этим циклом не выполнялась.

## Установка и запуск

1. Закройте Relay обычным способом. Запустите локальный [установщик Windows x64](../../release/1.5.0/Egoist%20Relay_1.5.0_x64-setup.exe). Проверка размера и SHA-256 — в [installer.json](installer.json), рядом с EXE есть SHA256SUMS.txt.
2. Установите обновление в прежний каталог приложения, сохраняя профиль. Установщик не подписан; готовность публичного выпуска не заявляется.
3. Запустите Egoist Relay из меню Windows или существующего ярлыка. Версия EXE должна быть 1.5.0. В обычной установке владельца EXE находится в `C:\Users\Egoist\AppData\Local\Egoist Relay\Egoist Relay.exe`.
4. Откройте Telegram и своё «Избранное». Не выбирайте других адресатов в этой приёмке.

## Основной сценарий: фото и видео

Используйте контролируемый пост с фото 3000×2000 и коротким роликом 1080p, доступный вам в X/Instagram. Разрешение после обработки исходной платформой может отличаться от исходного файла.

| Действие | Что проверить |
| --- | --- |
| Открыть диалог пересылки | Каждый новый диалог начинается с «Ссылка», до подтверждения ничего не отправляется |
| Сохранить медиа локально | Видны реальные этапы; процент только при известном объёме; после закрытия панели/переключения сервисов операция продолжается |
| Подождать исчезновения уведомления; Ctrl+J | Результат доступен в «Истории», есть путь/имя, размер и доступное разрешение; «Открыть файл» и «Показать в папке» ведут к результату |
| Закрыть Relay и запустить снова | История и опубликованный файл доступны; незавершённые операции помечены прерванными, отправки не повторяются автоматически |
| Новый диалог → «Медиа» → своё «Избранное» | Telegram показывает фото/видео обычным способом; обработка Telegram допустима |
| Новый диалог → «Файл» → своё «Избранное» | Получатель видит документ; скачайте его из «Избранного» и сравните SHA-256 с локально полученной версией того же медиа |
| Закрыть диалог до подтверждения | Операция не появляется; временный захват освобождается |

Сравнение байтов: используйте один неизменившийся источник и одинаковую выбранную версию. Сравнивать полученный Relay файл с оригиналом **до** обработки Instagram/X нельзя. При несовпадении между двумя свежими захватами зафиксируйте обе версии/размеры и поведение источника; не считайте режим «Файл» проверенным только по внешнему виду.

```powershell
Get-FileHash -LiteralPath 'C:\путь\сохранено-Relay.mp4' -Algorithm SHA256
Get-FileHash -LiteralPath 'C:\путь\скачано-из-Избранного.mp4' -Algorithm SHA256
```

## Прерывание и восстановление

- Во время сохранения нажмите «Отменить». Завершение не должно показывать частичный файл как готовый. Повторите через возвращение к источнику и новый захват.
- На отдельном тестовом медиа прервите связь вручную, затем восстановите её. Ошибка, отмена и ручной повтор должны быть различимы. Настройки прокси Windows/Lagom менять не требуется.
- Для аварийной проверки закройте процесс Relay во время тестового сохранения. После запуска операция прервана; файл с итоговым именем либо отсутствует, либо полностью опубликован. Чужие `.part` не удаляются.
- Прервите пересылку набора после первого подтверждения. Подтверждённые элементы остаются в «Избранном»; повтор допустим только для точно сопоставленного свежего набора и того же аккаунта. «Исход неизвестен» требует ручной проверки «Избранного» и не предлагает автоматическую отправку.
- Смените Telegram-аккаунт: повтор прежней пересылки заблокирован. При блокировке Telegram журнал скрыт и следующая отправка не стартует.
- Переименуйте один тестовый сохранённый файл в Проводнике. В истории остаётся запись; открытие объясняет недоступность файла.
- Очистите историю через предусмотренное подтверждение. Файлы должны остаться на диске. При частично сохранённом наборе «Сохранить набор заново» создаёт отдельную запись и не удаляет прежние файлы.

## Native интерфейс и второе окружение

Проверьте Ctrl+J при фокусе в Telegram, X и Instagram, переключение сервисов во время операции, FullHD/800×560, Tab/Escape, текст 200%, RTL и reduced motion. 640×448 проверено как browser viewport; текущий native минимум окна — 800×560. Для физической проверки DPI/GPU, реальных границ WebView и второй Windows-конфигурации нужны ваше устройство и отдельное второе устройство/участник.
