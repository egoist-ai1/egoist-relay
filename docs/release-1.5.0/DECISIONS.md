# Egoist Relay 1.5.0 — принятый объём

Дата: 6 октября 2026. Канонический проект: `Egoist Relay`; ветка `codex/relay-media-operations`.

## Шесть решений пользователя

1. Личный продукт для владельца и небольшого круга пользователей Windows.
2. Первый цикл: надёжное сохранение и пересылка медиа, включая результат после уведомления и сбоя.
3. Правая панель 24rem по кнопке/Ctrl+J; полный рабочий экран, если сервису остаётся меньше 40rem. WebView сохраняется.
4. Локальный журнал 30 дней, максимум 500 завершённых записей, DPAPI CurrentUser и отдельный ACL; очистка сохраняет файлы.
5. Перед отправкой Ссылка / Медиа / Файл, новый диалог начинается со Ссылки. Файл и локальное сохранение сохраняют полученные байты; исходная платформа могла обработать оригинал раньше.
6. Живая приёмка — владелец вручную отправляет только в своё Избранное после готовности кандидата. Агент не отправляет сообщения.

## Границы

Существующий стек Tauri/Teact/GramJS, локальные runtime-ресурсы, профили и системные правила маршрутизации сохраняются. Новых облачных зависимостей, регистрации Relay, телеметрии, монетизации и подписок нет. Настройки Windows и Lagom не меняются. Публичная публикация и обновление рабочего установленного приложения отдельно от создания локального установщика.

## Уточнения по фактическим краям реализации

- Один исполняемый Relay save/send и до восьми ожидающих. Обычные WebView-загрузки используют существующий транспорт и своего единственного native-владельца пути/завершения.
- После подтверждения диалога источник передаётся операции: переключение сервиса и закрытие панели не отменяют работу.
- Повтор возвращает к источнику. Пользователь повторно нажимает «Поделиться в Telegram»: свежий захват поддерживает фотографии, альбомы и текст, не зависит от истёкшей CDN-ссылки. До подтверждения новая попытка не начинается.
- Пересылка продолжает прежний ID, адресата и формат; свежий набор проверяется по SHA-256, подтверждённые элементы пропускаются. Исход неизвестен — только проверка чата, автоматического повтора нет.
- Частично сохранённый набор сохраняет прежнюю запись и файлы. «Сохранить набор заново» создаёт новую операцию всего набора: без надёжного соответствия элементов нельзя молча считать изменившийся альбом прежним. Сохранение без опубликованных файлов продолжает прежний ID с новой попыткой.
- Ошибка записи истории после фактического результата оставляет результат в памяти с предупреждением. После перезапуска его нужно проверить вручную. Перед отправкой ошибка записи намерения останавливает отправку.
- Общее событие epoch и attempt/revision защищают от поздних событий; блокировка немедленно скрывает журнал и не запускает следующую отправку.

## Критерии приёмки

Путь к файлу доступен в панели и после восстановления журнала. Закрытие диалога после подтверждения не отменяет операцию. Частичный файл не публикуется под итоговым именем; существующие файлы не заменяются. Неопределённая отправка показана явно, не повторяется автоматически. Новое сохранение/режим Файл не перекодируют полученные байты. Проверьте потерю связи, отмену, частичный успех, очистку истории, смену аккаунта, узкое окно, клавиатуру и reduced motion.
