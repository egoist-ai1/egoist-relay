# Egoist Relay 1.3.0 — повторный аудит и проверка сборки

Дата: 29–30 сентября 2026, Europe/Moscow. Аудит выполнен заново по фактическим исходникам, воспроизводимым отказам и новым проверкам. Установленный у владельца Relay 1.2.4 не заменялся. Исходная версия проверяемого проекта — 1.2.6; новый кандидат — 1.3.0.

**Статус: unsigned кандидат 1.3.0 собран; установка и основные нативные проверки завершены. Публичный релиз не готов.** В финальной личной сборке воспроизведён отказ YouTube `MEDIA_BOT_CHECK` через выбранный туннель; на generic маршруте тот же контрольный ролик воспроизводится. Кроме этого незакрытого сценария, публикацию блокируют неполные corresponding sources встроенных компонентов и отсутствие проверок чистого второго устройства и длительной сети. Владелец выбрал сборку без подписи.

## Объём работы

До реализации сохранены [план и критерии](PLAN-1.3.0.md), сведения о состоянии проекта и контрольные суммы исходных файлов. Независимо рассмотрены четыре области: [сеть](audit-1.3.0/network.md), [медиа](audit-1.3.0/media.md), [интерфейс](audit-1.3.0/ui.md), [упаковка и безопасность выпуска](audit-1.3.0/release.md). Для дальнейшей доводки подготовлены [система дизайна](DESIGN-1.3.0.md) и [план публичного выпуска](RELEASE-ROADMAP-1.3.0.md). Это аудит критических путей и связанных модулей, а не доказательство проверки каждой строки всех зависимостей.

Проверены путь приложения через собственные прокси, DoH и изолированный туннель; запуск, владение и восстановление помощников; bridge Telegram; загрузка, сохранение, отмена, clipboard и подготовка пересылки; YouTube iframe/native recovery; просмотр документов; оболочка Telegram/X/Instagram; deep links; IPC boundaries; зависимости, версии, CI и установщик. ## Изоляция и пределы сетевых гарантий

Relay использует собственные loopback listeners и управляет только принадлежащими ему процессами. Системные DNS, proxy, routes, Lagom и другие VPN не перенастраиваются. Помощники работают с пониженным приоритетом и принадлежат собственным worker jobs. Личный профиль — самостоятельная конфигурация внутри Relay, а не управление службой Lagom.

Неявные порты теперь обходят существующих listeners; явная конфигурация при конфликте прекращает запуск маршрута. Между выбором и bind остаётся неизбежная гонка, которая завершается отказом без принятия чужого процесса. Установленный main proxy не переключается произвольно на прямой интернет или иной VPN.

DNS destination изолирован выбранным route; **bootstrap hostname удалённого туннеля всё ещё разрешается системным DNS**. Поэтому утверждение «вообще весь DNS каждого пакета внутри туннеля» неверно. Generic package без личного профиля использует public DoH/DPI и не гарантирует доступ к Telegram, если сеть блокирует TCP дата-центров. DNS не заменяет удалённый tunnel endpoint.

Даже локальные статусы `ready` подтверждают работу собственных служб, а не успешный вход Telegram/X/Instagram. Авторский запрет YouTube, regional/account/bot restrictions и отказ сервера остаются возможны. Точный чужой Shorts и его сеть не получены; причина именно того отказа не доказана.

Установленные профили шифруются DPAPI CurrentUser; путь Xray относится к собственной папке Relay.

Неудачные ранние проверки сохранены: отсутствующий LICENSE в длинном пути, обход downgrade в `/S`, первоначальная NSIS fixture с неверным порядком plugin, отсутствие второго download event без нового user action, попытка shutdown во время навигации после reconnect. Ошибка ожидания теста «удалить посторонний runtime-файл» исправлена: unmanaged files сохраняются. Текущий пакет не удаляет прежний packaged runtime resource; при будущем удалении компонентов понадобится явная миграция. Эти случаи не скрываются общим числом пройденных unit tests.

## Что ещё мешает публичному production выпуску

**Незакрытый сценарий YouTube через личный туннель:** финальный контрольный запрос возвращает `MEDIA_BOT_CHECK`. Причина требования со стороны сервера и поведение после легитимной пользовательской проверки не установлены; точный Shorts второго пользователя неизвестен. Нужна проверка официального плеера/сайта на этом же маршруте и входа на выделенном тестовом аккаунте, затем воспроизведение Shorts. Бесконечный retry, молчаливый direct fallback или обещание «DNS всё исправил» этот gate не закрывают.

1. **Corresponding sources:** source ZIP и inventory подготовлены, но exact build inputs и dependency sources FFmpeg, ciadpi и egoist-tg-proxy не собраны полностью; часть npm/Cargo/Go/standalone dependencies только перечислена ссылками и hashes. `correspondingSourceComplete=false`, `publicationBlocked=true`; наличие архива проекта не закрывает этот gate.
2. **Другое устройство:** нет фактического install/login/media/upgrade/uninstall на чистом втором ПК без Lagom/dev tools. На текущем host WebView2 154.0.4258.37; заявленные Windows build 18362 и WebView2 143 требуют отдельной VM.
3. **Длительность и сеть:** не выполнены 24–72 часа, смена сети, сон/возврат, несколько VPN providers и длительные workload/RSS trends. Краткая проверка восстановления не позволяет обещать отсутствие переподключений.
4. **Подпись и публикация:** проверенная unsigned сборка соответствует выбору владельца. Publisher reputation, signed update channel и площадка публичного выпуска не настроены; updater отключён.
5. **Аккаунтные операции:** реальная отправка/пересылка, upload и authentication второго пользователя не выполнялись. Clipboard проверен синтетически без записи в системный clipboard.

Следующий план — получить недостающие исходники компонентов или заменить их воспроизводимо собираемыми эквивалентами, пройти чистую VM/второй ПК и длительный сетевой прогон, затем решить вопрос публичной площадки и подписи. Обещания «AAA», «без любых ошибок» и «всегда работает» результатами этого аудита не поддерживаются.
