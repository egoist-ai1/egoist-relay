# Egoist Relay 1.3.2 — исправления запуска, загрузки и входа

Проверка 30 сентября 2026 года на текущей Windows. Исследованы запуск и singleton, переключения оболочки, WebView2, маршруты авторизации X/Instagram, начальная авторизация Telegram, интеграция Windows proxy, native media и состав установщика. Исходный checkout содержал изменения: они сохранены, полный Git diff не является списком изменений этого аудита.

Nonce сообщения готовности связан с конкретным WebView и ID навигации. Проверяются source и текущий HTTPS-документ. Наблюдатель DOM не читает значения форм, credentials или cookies и прекращает работу после готовности. Для X сохранена подсказка прямого входа; Google OAuth во встроенных браузерах не объявляется поддерживаемым. Формат версионного Meta OAuth подтверждён [официальным SDK](https://github.com/facebook/facebook-android-sdk/blob/main/facebook-common/src/main/java/com/facebook/internal/WebDialog.kt).

## Маршрут Lagom и граница результата

Подробный [сетевой аудит](audit-1.3.2/network.md) подтверждает: системный proxy выключен, активный VPN/TUN не наблюдался; Telegram DC не достигают TCP, Instagram/Facebook получают TLS reset. Это отказ до проверки учётных данных. X HEAD отвечает 307, что не подтверждает загрузку JavaScript и вход.

Relay наследует системный маршрут Windows; native media заново выбирает Windows proxy на каждую операцию. Этот контракт сохранён из 1.3.1 и проверен существующими regression suites. Фиксированный порт Lagom, второй VPN/DNS/DPI engine и копирование профилей не добавлялись. Службы DNS/DPI/Telegram MTProxy в Lagom не гарантируют маршрут для WebView2 HTTPS/WSS. Сохранённый VPN выбран, но подключение выключено; у установленного Lagom не найден поддерживаемый фоновый VPN-connect API/CLI.

Для подтверждения Telegram QR/сессии и настоящих входов Instagram/X нужен рабочий маршрут Lagom. Пароли, OTP и сообщения в этом аудите не вводятся. Проверка долгой непрерывной работы, всех CDN, независимого ПК и авторизованных лент остаётся вне подтверждённого результата; безотказность в любой сети не заявляется.

## Нативная проверка и обновление

Новая сборка проверена через точный background binding в отдельном профиле. Первичное окно и все три WebView привязаны к запущенному процессу. Повторное использование `main` и отказ от внешнего URL проходят; число окон, локальный URL и metadata сохраняются. Повторные X → Telegram переключения три раза подтверждены состоянием sidebar. Для X и Instagram получены конечные ошибки Relay и выполнены кнопки «Попробовать снова»; X возвращается в загрузку, Instagram при том же сбросе сети снова завершается ошибкой. Системная страница ошибки Instagram и пустая X-страница скрыты.

Read-only пилот начинается перед холодным запуском: 952 наблюдения за 30 с, 0 попаданий Relay в foreground и 0 изменений clipboard. Мышь двигалась во время пилота; пользовательская активность не приписывается API. В коротком фоновом sample main WebView сообщает `visibility=visible`, медиану frame interval 16,7 мс, p95 16,8 мс, 0 long tasks за 1,5 с. Это не измерение всей авторизованной ленты или долговременной производительности.

Начальный script проверки не распознал русскую подпись «Попробовать снова» и счёл стандартные Edge error controls интерфейсом сервиса. Проверка исправлена и повторена; эти начальные выводы не используются как подтверждение загрузки. Generic click sidebar был запрещён адаптером из-за текста «Не удалось»; нативные переключения проверены штатным typed `switchService`. Гонка быстрых необработанных кликов воспроизведена в отдельном source fixture, не объявляется нативным стресс-тестом.

Установленный Relay обновлён с 1.3.1 до 1.3.2 штатным NSIS `/S` в прежней папке. Exit code 0. Все 37 installed runtime файлов совпадают по размеру и SHA-256 с manifest. До запуска профиля его top-level entries и timestamps не изменились. Копирование, logout и принудительное завершение аккаунтного процесса не выполнялись.

Установленный EXE побайтно совпадает с built EXE после штатной замены трёх байтов Tauri bundle-type `UNK` → `NSS`. Это проверено в памяти без изменения EXE и соответствует [исходнику использованного Tauri CLI 2.11.4](https://raw.githubusercontent.com/tauri-apps/tauri/tauri-cli-v2.11.4/crates/tauri-bundler/src/bundle.rs). Installed EXE SHA-256: `4794383e37bde5fbc3b41d043a01facb9f48fb7f1c9cca847e9078c2ab313478`.

Установленный EXE также запущен через поддерживаемый background launcher с прежним профилем. Все три WebView привязаны; оболочка, переключение X/Instagram и возврат в Telegram подтверждены. После возврата оба social WebView скрыты, page errors в наблюдавшихся snapshots — 0. Snapshot Instagram во время навигации сначала вернул `TARGET_NOT_READY`; последующее чтение подтвердило конечную ошибку, а не успешный вход. Этот тестовый запуск штатно завершён, чтобы следующий обычный запуск пользователя работал без background control mode.

Итоговый readback установленного запуска и точные hashes находятся в [verification.json](../release/1.3.2/verification.json). Снимки отдельного профиля: [X](audit-1.3.2/x-error.jpg) и [Instagram](audit-1.3.2/instagram-error.jpg).
