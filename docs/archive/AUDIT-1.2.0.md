# Аудит Egoist Relay 1.2.0

Дополнение к [полному аудиту 1.1.0](AUDIT-1.1.0.md): встроенные медиа в Telegram, отправка из X / Instagram и изменённая маршрутизация основного WebView. Зависимости не добавлялись. Учётные записи и пользовательские изменения сохраняются.

## Границы реализации

Встроенная карточка принимает только проверенные HTTPS-ссылки YouTube, Instagram и X. Адрес iframe строится по известному шаблону платформы. Удалённый код работает в отдельном iframe с ограниченным sandbox и не получает права IPC основного приложения. Сообщения YouTube API проверяются по origin и конкретному contentWindow; ошибке 153 не приписывается успешное воспроизведение. Используются [официальные параметры проигрывателя](https://developers.google.com/youtube/player_parameters), [Iframe API](https://developers.google.com/youtube/iframe_api_reference) и [требования идентификации](https://developers.google.com/youtube/terms/required-minimum-functionality#embedded_youtube_players).

Remote WebView X / Instagram передаёт только выбранную публикацию через отдельный native bridge. Проверяются собственный WebView, текущий HTTPS-origin, активный сервис, токен, схема запроса и срок действия. Подготовка файлов, отмена и показ выбора получателя разрешены только локальному main WebView. Удалённая страница не получает общий доступ к Tauri IPC.

Загрузчик принимает ограниченные CDN-адреса, проверяет публичные DNS-ответы, фиксирует адрес соединения, проверяет redirect, длину, формат и размер файла. Сетевое соединение создаётся через собственный SOCKS-прокси; прямой резерв не используется. Встроенный Node запускается без видимого окна; временные подписанные URL передаются через stdin и не сохраняются в аргументах процесса или отчётах. Завершение и отмена относятся к собственному дочернему процессу.

Отправка использует отдельную очередь с фиксированным получателем. Она не читает активный composer и не вызывает переход в чат. Перед каждой операцией проверяются ограничения получателя; серверный и локальный черновики сохраняются. Подтверждённые части не отправляются повторно. Новые флаги поведения включаются только этим сценарным вызовом; обычная отправка Telegram сохраняет прежний контракт.

Основной WebView получает тот же управляемый маршрут для удалённых iframe. Loopback и локальный WebSocket остаются в bypass. Telegram MTProto по-прежнему работает через собственный локальный мост. Локальная готовность служб не означает доступность любого внешнего CDN.

Исправлена обработка batched API-сообщений: исключение в одном UI update больше не прерывает получение следующих update и ответа на ожидающий RPC. Ошибка передаётся существующему обработчику; её содержимое не подменяет серверный ответ.

## Доказательства

Отчёты этой версии:

- `inline-media-verification.json`: реальные компоненты Teact / DOM, строгие URL, ошибки provider API, клавиатура, остановка и освобождение iframe.
- `social-share-verification.json`: выбор получателя, подготовка, независимая отправка, ограничения, повтор и сохранение черновиков на синтетическом клиенте.
- `social-share-native-verification.json`: собственный SOCKS / TLS, целостность файлов, ограничения адресов и native bridge.
- `connector-batch-verification.json`: ошибочный update, последующие события и завершение реального pending request в одном пакете.
- `native-verification.json`: сборка и проверка окончательного EXE через отдельный MCP.
- `installer-verification.json`: установка, payload и удаление в изолированной копии.
- `release-manifest.json`, `SHA256SUMS.txt`: хэши артефактов, исходников и отчётов.

Каждый отчёт указывает фактически проверенный слой. Синтетический Telegram RPC не объявляется доставкой в реальный аккаунт. Событие load iframe Instagram / X не объявляется доказательством начала видео.

Проверка первого собранного EXE выявила интеграционную ошибку Instagram: отсутствие текста сериализовалось как `null`, а строгий интерфейс ожидал отсутствие поля. Native-часть теперь опускает это поле. Добавлены 12 проверок реальной сериализации serde вместе с фактическим валидатором интерфейса; прежняя сборка заменена после исправления.

Окончательный EXE проверен через 18 инструментов выделенного MCP. В авторизованных профилях загрузились Telegram, X и Instagram; обе формы «Поделиться» открылись и закрылись, сохранив сервис и текущий маршрут Telegram. Существующий пост X отрисовался со своим видеоплеером внутри сообщения; начало самого видео не подтверждалось. При смене сервиса iframe освобождался. Полный перезапуск сохранил сессии; старый MCP получил `SESSION_CHANGED`, явное обновление приняло только новый ID и сбросило ссылки на прежние элементы.

Короткие фоновые замеры по 1,5 секунды: X / Instagram — медиана 16,7 ms, p95 16,8 ms; main — медиана 33,4 ms, p95 33,5 ms. Во всех трёх замерах длинных задач не было. Скрытое или перекрытое окно может ограничивать частоту кадров; эти результаты не доказывают скорость всех функций. Прокрутка Instagram проверена по фактическим позициям `0 → 240 → 0`. За 45 секунд наблюдения foreground Relay оставался неактивным в 221 отсчёте, clipboard сохранил sequence; положение системного курсора в начале и конце совпало. Глобального ввода не было.

Полные проверки TypeScript / ESLint, stylelint, production frontend, Rust и NSIS завершились с кодом 0. Остались 2 прежних предупреждения ESLint, 513 предупреждений stylelint и одно сообщение линковщика. Проверены 3079 неизменных входов сборки; production source maps отсутствуют. Отдельные feature-отчёты содержат 50 inline assertions с разделённым происхождением, 17 сценариев share, по 38 проверок транспорта HTTP/1.1 и HTTP/2, 8 случаев batched API и 3 проверки версии.

Изолированная установка сохранила байты всех 6 файлов поставки. Проверены установка, штатный выход, удаление, сохранность сторонних процессов с совпадающим именем и 9 исходных отпечатков пользовательской установки. При отдельном native-запуске с недоступным прокси основной UI и QR-вход загрузились; подтверждены loopback TCP-соединения с Telegram-мостом. Удалённый iframe в этом fallback-проходе не монтировался. WebView2 уже был установлен на машине; офлайн-пакет включён, первая установка на чистой Windows не проверена.

Для MCP отдельно проверены 16 случаев viewport / clipping и запреты pin / unpin / vote: 18 новых и 32 существующих policy-сценария. В самом окне попытка открепить сообщение вернула `ACTION_DENIED` без изменения сообщения. Отчёт installer фиксирует ранее проверенный hash MCP; позднее усиление запретов имеет свой hash и отдельный отчёт.

## Ограничения

Универсальное воспроизведение любой публикации, всех функций соцсетей и работа при любом системном VPN / DNS не подтверждены. Правила платформы, авторизация, блокировка встраивания, удаление публикации и доступность CDN остаются внешними условиями. В общей проверке реальные сообщения, публикации и платные операции не выполняются.

Передача доступных файлов из публикации имеет обозначенные лимиты и не является универсальным downloader потокового видео. После полного закрытия приложения неподтверждённая очередь этой операции не восстанавливается. Наблюдавшиеся в 1.1.0 сторонние ошибки Instagram и периодические сетевые отказы не объявлены полностью устранёнными.

При загрузке существующей карточки X наблюдались один анонимный `TypeError` и один сетевой отказ; пост и видеоплеер отрисовались. Точный источник этой ошибки не установлен. Проверки Shorts / Reels и реальной доставки выбранному получателю в текущих аккаунтах остаются вне подтверждённого runtime-охвата.

Установщик проверяется отдельно от реальной установки пользователя. Проверка через MCP привязана к точному процессу и его WebView; системный курсор, foreground и clipboard для управления не используются.

В текущем пользовательском окружении порт Telegram 1443 уже занят настроенным EgoistShield. Relay использовал подтверждённую локальную конфигурацию, не останавливая этот сторонний процесс. При выходе освободились принадлежащие Relay мост 1444 и DPI-прокси 1080; сторонний 1443 остался доступен. В изолированной установке проверены все три собственные службы. Отдельный встроенный DNS-daemon в этой версии не добавлялся.
