# Egoist Relay 1.2.5 — аудит медиа

Дата: 29 сентября 2026. Исходная установленная версия: 1.2.4. Этот отчёт охватывает медиа, буфер обмена, очередь скачиваний и передачу публикаций X/Instagram в Telegram. Общие результаты установки, UI и сетевых служб входят в основной отчёт релиза.

## Проверки

- **Frontend: 44/44** теста в 7 файлах. Настоящий clipboard, Telegram API и IPC заменены контролируемыми mock-объектами. Проверены ошибки/задержки копирования изображения и ссылки, URL, очередь скачиваний, текст документов, отмена inline-media, освобождение Blob URL, сохранение ID при повторе передачи.
- **Node: 19/19**, без пропусков. Локальные синтетические SOCKS/HTTP endpoint; ни один тест не подключается к реальному CDN, публикации или аккаунту. Проверены фрагментированные SOCKS-ответы, сохранение ранних данных, HTTP CONNECT/407, отказ неверного TLS endpoint, отмена сокета, allowlist gate, отсутствие локального DNS назначения, лимиты, окружение subprocess, cookies-injection, очистка успеха/ошибки и гонка `.part`.
- Проверен запуск обоих встроенных Node-worker через Windows `node --input-type=module -e`: общий модуль загружается без доступа к исходному каталогу, некорректный IPC завершается с `MEDIA_INPUT_DENIED`.
- Добавлены **4 native unit-теста**; основной агент подтвердил общий cargo gate **17/17**. Этот результат сам по себе не подтверждает успешность полной сборки установщика.
- Исходные отказавшие проверки сохранены в task-local evidence: Node 3 failed / 1 passed; clipboard/URL 8 failed / 11 passed; потеря второго скачивания; ложный таймаут сканирования фрагментов. После исправления соответствующие сценарии проходят.

Тестовые файлы: `src/util/{clipboard,inlineSocialMedia,resolveInlineMedia,download,documentClipboard}.test.ts`, `src/components/multi/socialShare.test.ts`, `src/components/middle/message/helpers/copyOptions.test.ts`, `scripts/{media-proxy,social-media-fetch}.test.mjs`. Полные логи временно находятся в runtime текущей задачи; в проект не копируются данные аккаунтов и содержимое буфера.

## Что эти проверки не доказывают

1. **Гарантированную доступность внешних сервисов.** X, Instagram и YouTube могут требовать вход, ограничивать публичные URL, менять API/HTML, блокировать IP или выдавать CAPTCHA. yt-dlp/ffmpeg остаются внешними компонентами с собственными ограничениями.
2. **Постоянную доступность зашифрованного туннеля.** Окончательная личная сборка использует общий Main/Telegram/X/Instagram/media маршрут через собственный SOCKS/DoH-шлюз 17880 и включённый Xray 17881 с выбранным VLESS/REALITY/xhttp stream-up профилем; DNS назначений проходит тот же backend. Это сохранённый профиль без живой зависимости от Lagom и прямого fallback. Media-тесты этого раздела не доказывают доступность удалённого сервера или окончательную установку; итоговый маршрут, DNS и pending release gates приведены в [основном отчёте](AUDIT-1.2.5.md).
   Прокси с логином/паролем в текущем контракте не поддерживаются; такая конфигурация отклоняется без перехода на прямое соединение.
3. **Отсутствие влияния любого стороннего VPN.** Приложение не меняет системные маршруты/прокси, но системный VPN, firewall или сбой сети может влиять на исходящие соединения выбранного endpoint. Реальная матрица конфликтов и длительный soak требуют отдельных наблюдений.
4. **Реальную отправку и списания Stars.** Тесты передачи этой медиа-подзадачи синтетические; отправка и изменение аккаунта не выполнялись. Основной аудит отдельно проверяет существующие профили и предварительный просмотр выбора получателя без отправки.
5. **Работу native OS clipboard или сохранение файла на диск в каждой версии WebView.** Clipboard/декодирование изображений проверены mock-объектами. Anchor-download проверяет запуск save-request; факт записи файла и отмена диалога ОС проверяются отдельно native/download-тестами релиза.
6. **Полную передачу любого альбома.** До 10 видимых CDN-вложений, 64 МиБ на файл и 128 МиБ суммарно. Публичный fallback рассчитан на одно видео до 600 секунд и совместимый формат; он не обещает полное извлечение каруселей, stories, live, закрытого или ограниченного содержимого. Если часть медиа недоступна, следует сверять состав с исходной публикацией.
7. **Повторяемость между перезапусками после неопределённой отправки.** Job сохраняет ID и подтверждённые части внутри текущей сессии; долговременного журнала передачи нет. Неопределённый результат API после закрытия процесса требует ручной проверки истории перед новой отправкой.
8. **Рынок или релиз без дефектов.** Здесь устранены наблюдаемые ошибки и добавлены регрессии. Длительная работа, реальные разные proxy/VPN, DPI и масштабы Windows, установка/обновление/откат и внешние account-flow оцениваются в общем отчёте отдельно.

## Оставшийся план проверки релиза

- Пройти полный TS/ESLint/CSS/cargo gate и собрать установщик из итоговых исходников.
- В изолированном профиле проверить реальные download complete/cancel и clipboard с разрешением пользователя на изменение OS clipboard.
- Для реальной пересылки согласовать конкретного тестового получателя и подтвердить запись сообщения в истории, включая retry после неопределённого исхода и платный чат.
- Провести длительный сетевой тест с выбранным app proxy и фактически используемыми VPN: reconnect, сон/пробуждение, смена Wi-Fi, отказ proxy endpoint, отсутствие перехода на прямую сеть.

Эти пункты обозначают недостающие доказательства. Они не отменяют выполненные исправления и не являются обещанием абсолютной доступности внешних сервисов.
