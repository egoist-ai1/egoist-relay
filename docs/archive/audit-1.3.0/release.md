# Аудит распространения, безопасности и сборки

Исходный аудит: 29 сентября 2026 года, версия **1.2.6**. Реализация release gates: 30 сентября, версия **1.3.0**. Таблица ниже сохраняет исходные воспроизведённые дефекты и первоначальные line locators; актуальные исправления и оставшиеся условия перечислены в конце документа.

Проверены конфигурация Tauri, Cargo/npm lockfiles, CI, updater, capabilities, deep links, NSIS hooks, общедоступный установщик и provenance runtime. Проверка выполнялась без установки поверх рабочего Relay, изменения реестра или системной сети. Личные enrollment-файлы, аккаунты и runtime других задач не читались. После аудита исправлены release scripts, CI, Vite statistics и требования установщика; package/config/Cargo изменения выполнил интеграционный агент.

## Порядок технических доработок

1. Закрыть Tauri2.11.5 high advisory и проверить boundaries на синтетических WebViews/несекретных payload.
2. Исправить CI identity/frontend, убрать автоматическую публикацию без validation; предусмотреть Windows-only выпуск до проверки иных платформ.
3. Ввести проверяемый release preflight: согласованная версия package/Cargo/public, identifier, dist mode, отсутствие test flags/enrollment, полный runtime manifest, locked inputs и обязательные тесты.
4. Исправить deep-link контракт; updater оставить явно отключённым до signed channel tests.
5. Задать OS/WebView2/downgrade requirements и проверяемый путь установки/upgrade/uninstall с отдельной тестовой identity.
6. Создать source/licensing package и manifest. Пакет нельзя собирать через `git add -A`/полную копию рабочего дерева: в нём есть private artifacts и локальные служебные файлы.
7. Проверить финальные архивы после bundling, включая точный executable/runtime, generic privacy, Unicode path и путь без dev tools. Не переносить результаты 1.2.6 автоматически на новый бинарник.

## Внешние и длительные условия публичного выпуска

- **Подпись и издатель.** Выбрать юридически корректное publisher identity, получить доверенную Windows подпись и timestamp. Подпись не гарантирует SmartScreen reputation. Для updater нужен отдельный key lifecycle/endpoint.
- **Источник и площадка публикации.** Определить адрес соответствующих source artifacts, privacy/support/security reporting и страницу загрузки. Аудит не публикует файлы и не создаёт внешние аккаунты от имени владельца.
- **Чистая VM/второй ПК.** Проверить реальный обычный installer на устройстве без Lagom, dev tools и владельческих профилей, с новым входом, restricted network, Windows Defender/firewall и другим DPI. Проверки клонированного installer на текущем ПК этого не заменяют.
- **24–72 часа наблюдения.** Сон/возврат, смена сети, VPN co-existence, длительные media workloads, memory/CPU/leak trends и controlled recovery. Число unit tests не заменяет эту проверку и не доказывает отсутствие переподключений.
- **WebView2 compatibility.** Evergreen runtime обновляется отдельно и может отличаться на каждом ПК; нужен минимум поддерживаемой версии и forward compatibility checks. [Microsoft distribution guidance](https://learn.microsoft.com/microsoft-edge/webview2/concepts/distribution).

Проверенный generic1.2.6 остаётся локальным неподписанным дистрибутивом с документированными ограничениями. После технических исправлений можно подготовить release candidate; статус публичного production выпуска требует закрытия внешних и длительных условий фактическими evidence.

## Дополнительный найденный дефект silent update

Root воспроизвёл реальный отказ downgrade guard в изолированной установке: существующий `DisplayVersion=1.4.0`, installer1.3.0 `/S` вернул0 и перезаписал executable/registry. Причина: Tauri сравнивает версии в `PageReinstall`, которую silent mode не вызывает; последующая `EarlyChecks` полагается на неинициализированный этим путём `$R0`. Само `allowDowngrades=false` оказалось недостаточным.

`tauri/installer.nsh` дополнен ранним `RelayCheckSelectedInstallVersion`: перед WebView2/files читает version resource самого installer, получает stable X.Y.Z, перечисляет uninstall records текущего SHCTX/registry view и выбирает только записи с InstallLocation, равным выбранному INSTDIR (с кавычками и без). Для их DisplayVersion выполняет `${VersionCompare}` из стандартного NSIS WordFunc (результат2 означает installed newer); более новая установленная версия приводит к **SetErrorLevel1/Abort**. Чужие директории и службы не затрагиваются. Такой guard работает до объявления VERSION/UNINSTKEY в генерируемом Tauri script и сохраняет изолированные product names тестового installer. PREINSTALL дополнительно проверяет точный product UNINSTKEY через `nsis_tauri_utils::SemverCompare` после выбора директории до копирования файлов, независимо от `$R0`/PageReinstall.

Первоначальная fixture помещала `!addplugindir` до hook и не обнаружила фактический template-order дефект: production generated script объявляет plugin directory позднее, поэтому early `nsis_tauri_utils::SemverCompare` не компилировался. Root воспроизвёл compile failure; ранний вызов заменён стандартным WordFunc VersionCompare. Новая fixture имеет plugin directory, VERSION/UNINSTKEY **после** hook и прошла (**makensis exit0**). Никакие installed registry keys или application executables этим подпотоком не менялись. Root повторяет фактические install/upgrade/downgrade испытания после rebundling; оба найденных отказа сохранены в отчёте, а compile test не объявляется исполнением downgrade guard.

**Политика неизвестных runtime-файлов:** silent update сохраняет файлы, не перечисленные новым payload. Это позволяет не удалить пользовательские модели или вручную добавленные данные. `runtime/` не очищается рекурсивно; произвольные файлы не становятся частью bundled allowlist. Для1.3.0 checked runtime inventory по-прежнему96файлов, packaged resource removals в этом обновлении не вводятся.

**Известное ограничение будущих обновлений:** если следующий payload перестанет поставлять ранее установленный ресурс, silent overlay может оставить его в старой installation. Такой migration требует явного списка прежних owned paths и удаления/замены только проверенных предыдущих hashes после остановки собственных helpers. Удалять всё неизвестное из runtime либо пользовательские модели — некорректная реализация этого migration. Наличие синтетического unknown file после upgrade само по себе не считается дефектом1.3.0.

## Найденный отказ на длинной папке установки

Root выявил ещё один реальный отказ: personal Unicode installer в глубоко вложенном task work вернул0, но не установил один из96runtime-файлов — `runtime/licenses/xray-dependencies/google.golang.org/genproto/googleapis/rpc@v0.0.0-20260526163538-3dc84a4a5aaa/LICENSE`. Полный путь превысил классический Win32 MAX_PATH. Этот первоначальный silent-success/partial-payload failure не считается успешной установкой.

Фактический компилятор — **NSIS3.11**. `ManifestLongPathAware` не устраняет отказ самостоятельно: NSIS прямо указывает зависимость от Windows long-path policy и отсутствие поддержки long paths у CopyFiles/CreateShortcut. Windows также требует одновременно registry opt-in и manifest. В этом исправлении системная политика не меняется и long-path support не объявляется. [NSIS attributes](https://github.com/NSIS-Dev/nsis/blob/master/Docs/src/attributes.but), [Microsoft path limits](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation).

Добавлен fail-closed `RelayCheckInstallationPath` до WebView2/files и повторно в PREINSTALL: **INSTDIR не более135 UTF-16 units**. Для текущего manifest самая длинная relative file path —119units, relative directory —111. File budget:260−1NUL−1separator−119=139; более строгий directory budget с8.3 margin:260−12−1NUL−1separator−111=**135**. При превышении installer выводит просьбу выбрать более короткую папку, ставит exit1 и не проходит к dependency/payload sections. Notice layout,96файлов и pinned hashes сохранены.

`release-preflight` и `release-sources` вычисляют budget из frozen manifest и отвергают несоответствие installer constants; следующая версия runtime не сможет незаметно добавить более длинный путь. **10/10 policy tests PASS**. Actual isolated NSIS fixture с реальным hook, version resource и plugin declaration в production order дала **3/3 PASS**: Unicode INSTDIR105units и boundary135 —exit0/marker после guard;136units —exit1/marker отсутствует. Fixture создаёт только собственный marker в task work, не устанавливает приложение и не пишет registry. Эти проверки доказывают исполнение path guard; полный96file payload в допустимой Unicode папке отдельно проверяет root.
