## Этап 2 · Интерфейс A «Тихая рамка+» (сделан 25.10, без пунктов «не сделано»)

- Состояния на иконке rail: сон (X, Instagram), «вход слетел», загрузка; тултипы со временем и причиной.
- Плашки в строке заголовка: сеть (узел N/M), память, операции; всплывающая сводка.
- Пустые состояния сервисов: причина + следующий шаг («Разбудить», «Войти заново», «Открыть журнал»).
- Критерии: отклик ≤ 100 мс; WCAG 2.2 AA (контраст, фокус, клавиатура, подписи состояний не только цветом); reduced motion; без потерь данных и входов.
- Нужны события из Rust: состояние сервиса (сон/вход), узел туннеля, суммарная память процессов.

Сделано 25.10.2026 [проверено на изолированном UI с подменённым нативным слоем: `scripts/qa-lagom/shell-states.mjs`, тёмная и светлая темы, 1280×800 и 640×448; на живом окне приложения не смотрели]:
- Плашки в заголовке (`StatusPlates`): сеть (Туннель / Только DNS / Нет сети / Запуск / Нужен перезапуск / Без VPN; форма точки — заливка, кольцо, пунктир; нажатие открывает настройки сети) и память всех процессов приложения (команда `relay_memory_usage`: рабочие наборы потомков процесса; опрос раз в 10 с, пока окно видно). Контраст подписей 5,3–19,8:1; в окне уже 58 rem память скрывается, уже 44 rem остаётся одна точка с подписью для читалок.
- Иконки rail: подсказка сна со временем («Спит с 14:32 — откроется за секунду»), время фиксирует интерфейс в момент события.
- Пустые состояния X и Instagram: при недоступном маршруте сети — причина (состояние сети) и кнопка «Настройки сети» (открывает настройки, как значок шестерёнки).
- Отклик «Настройки сети» из пустого состояния 48–62 мс; ошибок страницы нет; тесты: vitest 702 пройдено, `cargo test --lib` 278 пройдено.

Отступления от плана и что осталось:
- Всплывающей сводки нет: нативные окна X и Instagram перекрыли бы выпадающий блок поверх них. Вместо неё — подсказка плашек и открытие настроек сети по нажатию. Плашка «операции» не дублируется: у кнопки загрузок в заголовке уже есть счётчик.
- Узел туннеля «N/M» не показывается: статус сети не отдаёт индекс текущего узла (нужны события из Rust).
- «Вход слетел» для Instagram не показывается: оболочка не определяет потерю входа (у X есть состояние `auth-required`).
- Кнопки «Разбудить» и «Открыть журнал» не добавлены (разбудить можно выбором иконки; журнал — вне объёма).

## Этап 3 · Ресурсы (A цели): код готов 25.10, эффект не измерен

**Замер до правок** (установленная 1.9.10, работает 2 ч, 25.10): 1945 МБ, 31 процесс. Telegram ≈627 МБ, X ≈549, Instagram ≈507, Node 116, tg-ws-proxy 76, xray 43, conhost 28.

**Найденный дефект** (подтверждён архитектором): X и Instagram, созданные прогревом (`multi_prewarm_*`), никогда не усыплялись, пока их не показали и не скрыли, — ≈1056 МБ рабочего набора. Ещё: скрытый сервис, чья загрузка закончилась позже таймера, не засыпал; пропущенный Suspend (звук, загрузка, research-окно) не повторялся; `armed` не сбрасывался после расписания.

**Сделано** (`multi_app.rs`, `multi_app_sleep.rs`):
- `schedule` после прогрева X и Instagram (если сервис не активен) и в `complete_service_load` для скрытого сервиса.
- Пропущенный Suspend повторяется каждые 5 мин, не более 12 раз; отказ WebView2 в колбэке не повторяется.
- `Slot::release` снимает «таймер стоит» по завершении расписания, не меняя поколение; уже усыплённый сервис повторно не планируется, Low не затирает уровень Suspended.
- Тесты: `cargo test --lib` — 281 пройдено, 0 не пройдено (+3 теста сна).

**Не проверено:**
- Выигрыш `TrySuspend` на X/Instagram: ожидается снижение в основном renderer (217/243 МБ), процессы browser/gpu/utility окружения останутся. Проверка — после установки сборки владельцем: журнал «sleep level suspended» и повтор `relay-mem.ps1`.
- Будят ли `eval` спящий WebView: в коде eval к скрытым сервисам не найден, живой проверки нет.

**Отложено (решение архитектора):** закрытие WebView при долгом сне (≈2 ч) и общая среда WebView2 для X+Instagram — выигрыш против риска для входов не оправдан без замера после этого этапа.

## Этап 4 · Интерфейс B «Палитра команд»

**Решение архитектора:** индекс в памяти, без SQLite/FTS5 и без хранения на диске: данных на несколько тысяч записей хватает для линейного поиска за единицы миллисекунд, а хранилище добавило бы приватность и срок хранения без выигрыша. Индекс собирается при открытии палитры и не переживает закрытие.

**Что индексируется:** названия и @username чатов и контактов Telegram из уже загруженного состояния, «Избранное»; журнал сохранённого (только завершённые `save`/`download`: имя файла, сервис, хост и путь источника без query и fragment; полный путь файла не индексируется); статические действия. Тексты сообщений, подписи, телефоны и черновики не индексируются. Поиск по тексту сообщений — действие «Искать в сообщениях Telegram»: открывает штатный глобальный поиск, сеть только по Enter. Живой поиск в X и Instagram не выполняется.

**Сделано:**
- `multi/commandPalette.index.ts` (нормализация NFKC, «ё»→«е», слово названия → ключевое слово → подстрока от 3 символов), `commandPalette.saved.ts`, `CommandPalette.tsx` на `ui/Modal`: combobox/listbox, стрелки, Enter, Shift+Enter (показать файл в папке), Esc, `aria-live` с числом результатов.
- Ctrl+K (в macOS Cmd+K) перехватывается в основном окне; в редакторе с выделением остаётся «ссылка». Прежнее `Mod+K` быстрого выбора чата в `LeftColumn` удалено.
- Из нативных окон X и Instagram сочетание приходит событием `relay-palette-toggle` из Rust (`match_shortcut` в `multi_app_downloads.rs`, только метки X/Instagram и без оверлея шаринга); на время палитры нативные окна скрываются, как при полноэкранной панели операций.
- Проверки: `vitest` — 713/713, `cargo test --lib multi_app` — 35/35, сценарий `scripts/qa-lagom/palette.mjs` (две темы, 1280×800 и 640×448): 76 проверок, контраст 4,93–13,46. Сценарий нашёл дефект (`event.nativeEvent` в Teact не существует) — исправлен.

**Не проверено:**
- Перехват Ctrl+K из живых WebView X/Instagram и возврат фокуса между WebView2 (нужна установленная сборка и вход владельца).
- Достаточно ли загруженного при старте списка чатов Telegram: редкие чаты находятся действием «Искать в Telegram», а не из палитры.
- Отклик на 3–5 тыс. чатов в живом приложении (юнит-замер на 10 000 записей — меньше 100 мс), поведение каретки при кириллице в WebView2, чтение NVDA.
